========================================================================
maccms12（ThinkPHP 8）说明
========================================================================
本文档基于官方 maccms10「定时任务说明」整理。maccms12 定时任务机制不变：
后台「定时任务」配置任务，服务器 cron 周期请求 api.php/timming/index 触发。
· 任务调度入口：http://域名/api.php/timming/index（GET）
· 参数：name=任务名称（指定执行某条）；enforce=1（强制执行，跳过时间窗口）
  ※ enforce 是高权限参数：maccms12 只在「后台已登录管理员发起」时才认它
    （后台「测试」按钮会带管理员会话）；外部 cron 的匿名请求带 enforce=1
    会被忽略，照常走时间窗口判断，不会每次都真跑。
· 判断逻辑：任务配置的 weeks（周几）/ hours（小时）命中后才执行对应操作；
  另外可设「执行间隔(秒)」，>0 时改按距上次运行的间隔秒数判断（需外部触发器
  足够频繁），=0 时维持周几+小时的小时级判断。
· 官方 maccms10 的 5 种操作：collect 采集 / make 生成 / cj 采集规则 /
  cache 清理缓存 / urlsend 推送；maccms12 另有 extsync / vodpublish /
  analytics / notify / pushbroadcast / user_access_purge / annotate /
  content_quality / user_profile（详见文末）。
· 定时任务执行操作对应的后台模块：采集资源库=Collect、生成静态=Make、
  采集规则=Cj、清理缓存=Cache、网址推送=Urlsend（后台「定时任务」里选择执行文件）
· 定时任务配置文件：app/extra/timming.php（后台保存后生成）
· 常用 cron 示例（每 10 分钟执行一次）：
  */10 * * * * curl -s "http://域名/api.php/timming/index" >/dev/null 2>&1

========================================================================

定时任务目前的执行文件（后台「站点参数 → 调度任务」的「执行文件」下拉，共 14 项）：
collect / make / cj / cache / urlsend / extsync / vodpublish / analytics /
notify / pushbroadcast / user_access_purge / annotate / content_quality /
user_profile。
（上文官方原文只写了「采集资源、生成静态 2 个」，是 maccms10 时代的说法；
后 9 个是 maccms12 新增，见本文末尾「6，maccms12 新增的执行文件」。
另外，若某条任务的执行文件是手工写进 app/extra/timming.php 的自定义值、不在这 14 项里，
编辑页会把它作为额外一项选中并原样保存，不会被下拉改写。）
强制执行参数enforce=1

1，采集资源
执行文件：选择 采集资源库collect
附加参数：从自定义资源列表中获取（在采集今日，采集本周，采集全部 右键复制链接）截取参数部分即可。

例如：
任务名称：cj_day
任务描述：采集当天数据
附加参数：ac=cjall&h=24&xt=1&ct=&cjflag=b9c546ba925d22ed654927b44638df34&cjurl=http://cj.tv6.com/mox/inc/youku.php

执行文件：选择生成make
附加参数：

生成谷歌sitemap  ac=rss&ac2=google

参数id=1，参数就是当前采集自定义采集规则的编号。

6，maccms12 新增的执行文件
执行文件：在后台「站点参数 → 调度任务」的「执行文件」下拉里选择，共 14 项（前 5 项见上文 1~5）。
下拉里的实际文案（app/lang/zh-cn.php 的 admin/timming/* 键）：
  自定义采集collect / 静态生成make / 自定义采集规则cj / 清理缓存cache / 网址推送urlsend
  外部资源同步 / 视频定时上架 / 运营统计 / 通知中心 / Web推送广播 / 用户访问日志清理/匿名化
  AI内容标注 / 内容质量分计算 / 用户画像计算
（上文 1~5 沿用的是官方 maccms10 原文的旧叫法「采集资源库 / 生成 / 采集规则」，指的同一项，
按上面这份文案找即可。）
调度入口与参数格式与官方一致：附加参数是一串 query 风格字符串，由 controller 里
parse_str() 解析。处理器都在 app/api/controller/Timming.php。

6.1 外部资源同步 extsync
    到点执行「AI 搜索」配置页（system/configaisearch）里「外部数据源」段中到期的同步作业。
    参数：provider=数据源标识（留空表示遍历所有到期的源）
    示例：provider=tmdb
         provider=douban
    执行文件：选择「外部资源同步」
    备注：安装时预置的 tmdb_sync / douban 两条任务默认 status=0（未启用），需手动打开。

6.2 视频定时上架 vodpublish
    把到了上架时间的草稿/待发布视频转为已审上架（vod_status 3=草稿、4=待发布，
    vod_publish_time 为 Unix 时间戳；到点才由本任务放行）。
    参数：limit=单次处理条数（默认 200）
    示例：limit=200
    执行文件：选择「视频定时上架」

6.3 运营统计 analytics
    把明细访问日志汇总成报表数据，供后台统计页读取。
    参数：mode=hour|day（默认 hour）；date=指定日期（留空为当前小时/今天）
    示例：mode=hour
         mode=day
    执行文件：选择「运营统计」
    建议：hour 模式配成每小时触发一次，day 模式另建一条任务每天凌晨触发
    （安装时已预置 analytics_hour / analytics_day 两条，都是这个用法）。

6.4 通知中心 notify
    给即将到期的会员发送续费提醒（站内信/通知）。
    参数：days=提前天数（默认 3；填 0 或负数一律按 3 处理）
    示例：days=3
    执行文件：选择「通知中心」

6.5 Web推送广播 pushbroadcast
    Web Push 全员广播：后台点「广播」只入队，本任务逐条 HTTPS POST 异步分批发出。
    参数：batch=单批订阅数（默认 100）；max=单次运行处理上限（默认 500）
    示例：batch=100&max=500
    执行文件：选择「Web推送广播」
    备注：预置任务 push_broadcast 把「执行间隔(秒)」设为 60，即每分钟派发一批。

6.6 用户访问日志清理/匿名化 user_access_purge
    到期清理 + 匿名化用户访问风控日志（保留期与匿名化天数取自「安全与风控 → 访问风控设置」的
    retain_user_access_days / user_access_anonymize_days；后者必须早于前者，否则会被
    自动收敛为 retain-1）。
    参数：max=单次处理行数上限（默认 5000，建议每小时触发摊平逐行匿名化的压力）
    示例：max=5000
    执行文件：选择「用户访问日志清理/匿名化」

6.7 AI内容标注 annotate
    批量为内容生成 AI 标注（标签/简介类）。每次运行只挑 limit 条尚未标注的，做完即走；
    ContentAnnotator 内部按 source_hash 判重，重复触发不会重复消耗额度。
    参数：mid=1|2（1=视频、2=文章，其它值回落 1）；limit=单次条数
         （留空取「AI 能力 → AI 标注设置」页 system/configaicontent 的批量条数 ai_content.batch_size，
          取值范围 1~100、默认 20；填了 limit 也不会超过该配置值）
    示例：mid=1&limit=50
    执行文件：选择「AI内容标注」
    备注：未开启 AI 内容功能时处理器直接返回，不产生调用；预置任务 content_ai_annotate
         （param=mid=1&limit=50，每天 02 点）默认 status=0，需手动打开。
    （方法名 annotate 刻意不叫 aicontent，避免与 addons/aicontent 插件同名误导。）

6.8 内容质量分计算 content_quality
    离线计算内容质量分（无 LLM 参与），结果供后台「内容质量」看板读取；按 upsert 落表，
    可重复调度。选取顺序按打分新鲜度轮转：从未打分的内容优先，其次是打分时间最旧的，
    多次调度即可遍历全量，而不是永远只算最新的 limit 条。
    参数：mid=1|2（1=视频、2=文章，其它值回落 1）；limit=单次条数（<1 回落 200）；
         days=行为统计回溯天数（<1 回落 30）
    示例：mid=1&limit=200&days=30
         mid=2&limit=200&days=30
    执行文件：选择「内容质量分计算」
    备注：权重与衰减取 analytics.quality_weights / quality_fresh_halflife_days；
         安装时预置 content_quality（mid=1，03 点）、content_quality_art（mid=2，04 点），
         默认 status=0。

6.9 用户画像计算 user_profile
    批量构建用户画像（供推荐/统计使用），按 user_id upsert，可重复调度；
    候选用户按画像更新时间轮转，从未算过的优先。
    参数：limit=单次用户数（<1 回落 200）；days=画像窗口天数（<1 回落 30；
         若 app/extra/maccms.php 里配了 analytics.profile_window_days 则以它为准——
         该键没有后台输入框，system/configanalytics 页只提供 server_track / track_region）
    示例：limit=200&days=30
    执行文件：选择「用户画像计算」
    备注：预置任务 user_profile（param=limit=200&days=30，每天 05 点）默认 status=0。
