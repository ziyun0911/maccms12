## 1. 进后台的三道门

请求 `admin.php` 时依次发生（[admin.php:15-62](.../admin.php#L15)）：

| 顺序 | 检查 | 不满足时 |
|---|---|---|
| 1 | PHP 版本 ≥ 8.0.2（[admin.php:6-8](.../admin.php#L6)） | 直接 die 出版本提示 |
| 2 | `app/data/install/install.lock` 存在（[admin.php:33-36](.../admin.php#L33)） | 302 跳去 `install.php` |
| 3 | 登录态（[Base.php:18-52](.../app/admin/controller/Base.php#L18) → [model/Admin.php:166](.../app/common/model/Admin.php#L166)） | 跳登录页；AJAX 请求返回未登录 JSON |

PATHINFO 由入口脚本手工重算（GBK→UTF-8 纠正在 [:39-40](.../admin.php#L39)，结果同时写回 `$_SERVER['PATH_INFO']` 与 `$_GET['s']`，[:57-58](.../admin.php#L57)），
随后 `$app->http->name('admin')` 固定应用名（[:48](.../admin.php#L48)），并在启动框架前调 `mac_load_extra()`（[:60](.../admin.php#L60)）把 `app/extra/*.php` 全部读进 `$GLOBALS['config']`。

`Base.php` 构造函数还做四件对运营有直接影响的事：

1. **核心文件哈希闸门**：用 `app/extra/version.php` 里的 `update_hash` 校验 `app/admin/controller/Update.php` 的 md5，
   不匹配直接 `exit`——表现为**后台整站白页**（[Base.php:18-52](.../app/admin/controller/Base.php#L18)，详见 09 §5）。
2. **登录白名单只有 `Index/login`**（外加 `api/Timming/index`），其余控制器一律要登录。
3. `_pagesize` / `_makesize` 取 `app.pagesize` / `app.makesize`（[Base.php:43-44](.../app/admin/controller/Base.php#L43)），列表页每页条数改这里。
4. 除 `Update` 类外，每个动作先过 `check_auth($控制器, $动作)`——**权限不足是「操作失败」而不是 403 页面**，别当成 bug。

## 2. 登录、账号与安全设置

> 这一节只讲「后台里在哪儿改、改完有什么后果」。登录校验、哈希、会话、Cookie 自动登录的机制细节全部在
> `09-安全与权限手册.md` §2（登录）与 §3（权限模型），此处不重复。

- 表单提交 → [admin/Index.php:20-32](.../app/admin/controller/Index.php#L20) → 校验在 [model/Admin.php:108-156](.../app/common/model/Admin.php#L108)。
- **图形验证码**由 `app.admin_login_verify` 控制，出厂值 `1`（开启），设为 `0` 才跳过 `captcha_check()`（[Admin.php:114](.../app/common/model/Admin.php#L114)）。
  它是后台**唯一的减速手段**——后台登录没有失败计数、没有锁号、没有限流（09 §2 末尾的警告），所以「关验证码」是部署决策，不是便利开关。
- **口令哈希是 bcrypt**；历史 md5/明文可继续登录，成功后惰性升级为 bcrypt（机制见 09 §2）。
  对操作者的唯一影响：`admin_pwd` 列不足 60 字符时 bcrypt 装不下、会被静默退回 md5，**升级老库先核对列宽**。
- 「解锁」弹窗（改敏感设置前二次输密码）走 [Index::unlocked()](.../app/admin/controller/Index.php#L240)，它只校验当前登录者自己的密码。
- 管理员维护页：**用户 →「管理员」**（[admin/Admin.php](.../app/admin/controller/Admin.php)）。
  删除时**只挡住「删自己」**（[:127](.../app/admin/controller/Admin.php#L127)）——没有「必须留一个超管」的保护，删账号前先确认库里还有可用管理员。
- `admin_id = 1` 在 `check_auth()` 里无条件全放行，权限组对它不起作用（09 §3）。

## 3. 界面骨架：顶栏、左菜单、快捷菜单

- 左菜单来自 [app/admin/common/auth.php](.../app/admin/common/auth.php) 的 16 个分组数组，构建在 [Index.php:40-120](.../app/admin/controller/Index.php#L40)：
  **`show == 1` 且 `check_auth()` 通过**才渲染；`param` 字段会拼进 URL（同一个页面靠不同参数变成多个菜单项）；整组为空时该组不显示。
  `show=0` 的项不是不存在，而是**藏在页面内部链接里**（例如「评论留言配置」「URL地址配置」的子 tab）。
- 「自定义菜单配置」（首页组）保存的是**快捷菜单**：POST + 令牌，条目按 `chr(13)` 分行，落盘为 [app/extra/quickmenu.php](.../app/extra/quickmenu.php)（`mac_arr2file`，[Index.php:183-189](.../app/admin/controller/Index.php#L183)）。
  每行格式是 `名称,地址`，`qm_divider,###` 表示分隔线；读取时优先 `config('quickmenu')`，**为空才回落到旧文件** `app/data/config/quickmenu.txt`（[:76-79](.../app/admin/controller/Index.php#L76)、[:195-200](.../app/admin/controller/Index.php#L195)）。
  快捷项以 `900000+` 的 id 注入首页组，顶栏可一键跳转。
- 「系统信息」组由 [app/common/util/SystemSettingsMenu.php](.../app/common/util/SystemSettingsMenu.php) 的 `build()` 按 `check_auth('system', 动作)` 逐项门控（调用点 [Index.php:111](.../app/admin/controller/Index.php#L111)），所以不同账号看到的条目数不同。

### 5.3 保存之后会发生什么

- **搜索联动**：启用了 Meilisearch 时，保存走 `MeilisearchSync::afterVodSave()`（[model/Vod.php:848](.../app/common/model/Vod.php#L848)），删除走 `deleteVod()`（[:906](.../app/common/model/Vod.php#L906)）。
  站内 `vod_search` 只在**新增**那一条上打点：`checkAndUpdateTopResults()` 挂在插入分支里，且要 `vod_search_optimise` 含 `frontend`（[:835-837](.../app/common/model/Vod.php#L835)）。
  **编辑已存在的视频不碰这张表**，删除也不会从结果列表里摘掉它——列表里的悬空 id 由同一条查询里的 `vod_status = 1`（[:296](.../app/common/model/Vod.php#L296)）等条件挡掉，不会漏进搜索结果；
  旧列表真正被改写，要么等下次有人搜这个词，要么等 `clearOldResult()` 按 `vod_search_optimise_cache_minutes`（出厂 20160 分钟）整行清掉重建。
  读侧捷径的两个阈值与实测（热榜宽度 50000→1000、`search_result_count > 1000` 就退回 `LIKE`）见 [02-站点配置参考.md §7.2](.../说明文档/02-站点配置参考.md)。
- **分类缓存**：分类保存后 `setCache()` 重建（见 §6）。
- **静态化**：保存不会自动重生成静态页；要跑「生成」组或定时任务（[04 手册](.../说明文档/04-前台模板与静态化手册.md)、[07 手册](.../说明文档/07-定时任务与运维手册.md)）。

  自动规则在「视频 → 审核自动规则」（[app/admin/controller/VodAuditRule.php](.../app/admin/controller/VodAuditRule.php)）。
- **附件落盘**：上传的文件写到 `upload/<flag>/`（[model/Upload.php:76](.../app/common/model/Upload.php#L76)），远程存储模式改的是站点配置 `upload` 分区。

## 6. 视频专属：播放地址的三段格式（最容易出错的地方）

一个视频的多条线路在数据库里是**四个平行字段**，用同一种分隔规则一一对应：

```
vod_play_from   ：  线路A$$$线路B
vod_play_server ：  资源服A$$$资源服B
vod_play_note   ：  备注A$$$备注B
vod_play_url    ：  第1集$地址1#第2集$地址2$$$第1集$地址3#第2集$地址4
```

- `$$$` 分**线路**，`#` 分**集**，每集内 `名称$地址[$播放器]`——第三段可临时覆盖该集的播放器
  （[common.php:1733-1794](.../app/common.php#L1733) 拆线路，[:1943-1965](.../app/common.php#L1821) 拆集）。
- 只写 `名称` 不写第二个 `$` 时，整段被当地址、集名自动补「第N集」（[:1950-1955](.../app/common.php#L1828)）。
- 表单里每条线路是一个多行文本框：**行 = 集**，保存时数组 `join('$$$')`、换行统一替换成 `#`（[model/Vod.php:773-780](.../app/common/model/Vod.php#L773)）。
  因此**粘贴内容里混入 Windows 换行、空行、多余 `$$$` 都会变成集数错乱或空集**——排查播放列表异常先看这里。
- 截图字段 `vod_pic_screenshot` 同样用 `#` 分隔（[:771](.../app/common/model/Vod.php#L771)）。
- 线路名（`from`）必须能在「播放器」注册表里找到，否则前台不显示该线路；播放器/服务器/下载器三张注册表的机制见
  [10-插件与扩展手册.md §11](.../说明文档/10-插件与扩展手册.md)。
- **播放失败统计**（视频组最后一项）记录前台报错回收上来的失败地址，是定位坏线路的最短路径。

漫画同理：`manga_play_from/url/server/note`，解析函数 [mac_manga_list()](.../app/common.php#L1844)。

### 6.1 豆瓣反查：按片名填豆瓣ID

视频编辑页「豆瓣评分 / 豆瓣ID」右边的**查询数据**按钮，2026-11-04 起不再请求已停服的
`api.maccms.la`，改为本地接口 `admin.php/vod/doubanLookup.html`（POST `name`），
实现见 [Vod::doubanLookup()](.../app/admin/controller/Vod.php#L691)，底层用
[DoubanExternalSourceProvider::search()](.../app/common/util/DoubanExternalSourceProvider.php#L23)
打豆瓣 `subject_suggest`。

- **前提**：系统设置 → AI 搜索设置里「启用外部数据源平台」和「启用 Douban」都要打开，否则只返回提示。
- **命中一个**直接填入；**命中多个**弹窗列出「标题 / 译名 / 年份 / ID」由你点选，程序不替你猜。
- **评分不会自动填**：豆瓣 suggest 的返回体里根本没有评分字段（实测只有 `id/title/sub_title/year/img/url/type/episode`），
  而豆瓣词条页对匿名请求只回反爬占位页，抓不到 `v:average`。代码只在返回值 > 0 时才写 `vod_douban_score`，
  所以既填不进假分，也不会清空已有分。要成批拿到评分见 §6.2，要单条换 TMDB 源得配 api_key。
- 结果按片名进 `ext_search_cache`（受 `cache_ttl` 控制）并落 `mac_ext_source_item`；命中缓存时不打外网。
- 权限节点 `vod/doubanLookup`（auth.php gid 4406，`show=0`），子管理员默认**没有**该权限，
  要在管理员编辑页权限树勾选「豆瓣反查ID」。
- 豆瓣对匿名请求按 IP 突发限流：连点会返回空列表。实测 90 秒冷却 + 每次间隔 20 秒以上可稳定拿到结果。
- Windows 版 PHP 若没配 `curl.cainfo`，对豆瓣的 HTTPS 校验会失败（curl errno 60），
  表现同样是「未找到匹配的豆瓣条目」，排查时先分清是限流还是证书。

### 6.2 豆瓣评分回填：把榜单分数成批写进视频表

**查询数据**一次只填一条。要成批拿分，走「榜单同步 → 按 ID 回填」两步，两步都能手工触发也能挂定时：

**前提**同 §6.1：AI 搜索设置里「启用外部数据源平台」+「启用 Douban」都得打开；两个任务出厂 `status=0`，
要自动跑就在定时任务里分别启用 `douban`（同步）和 `douban_score_fill`（回填）——只开一个不会有变化。

1. **同步**：AI 搜索设置 → Douban 区块的「立即同步豆瓣」按钮，或定时任务 `douban`（`file=extsync`）。
   它打豆瓣 `j/search_subjects` 榜单（匿名请求里唯一能拿到 `rate` 的接口），
   把条目标题和分数一并写进 `mac_ext_source_item.item_score`。
   三个出厂字段决定抓多少：**单次同步条目上限** `sync_limit`=600、
   **豆瓣榜单频道** `recent_types`=`movie,tv`、**豆瓣榜单标签** `recent_tags`=`热门,最新,经典`，
   即 2 频道 × 3 标签 = 6 次请求（[DoubanExternalSourceProvider::fetchRecent()](.../app/common/util/DoubanExternalSourceProvider.php#L49)）。
2. **回填**：定时任务 `douban_score_fill`（执行文件选「豆瓣评分回填」，附加参数 `limit=1000`），
   用 `vod_douban_id` 去 `mac_ext_source_item` 找同 ID 的分数写进 `mac_vod.vod_douban_score`
   （[DoubanScoreFillService](.../app/common/util/DoubanScoreFillService.php#L42)，
   派发入口 [Timming::doubanscorefill()](.../app/api/controller/Timming.php#L163)）。

口径（2026-11-05 本机实测）：

- **只填空值**：默认只写 `vod_douban_score=0` 的行，已有分不覆盖；要覆盖加参数 `overwrite=1`。
- 改写按主键分批发（同分值的行合成一条 `UPDATE ... WHERE vod_id IN (…)`，每批 500 个 ID），
  内容表是 MyISAM、`vod_douban_id` 无索引，所以**不能**按豆瓣 ID 逐行 UPDATE。
  不碰 `vod_time`，免得采集接口误判「全站刚更新」；改过的行删 `vod_detail_<id>` / `vod_detail_<en>` 详情缓存。
- 分数四舍五入到一位小数（列是 `decimal(3,1) unsigned`），`<=0` 或 `>10` 的脏值丢弃。
- **覆盖率受豆瓣榜单体量限制**：本机一次同步得 316 条带分条目，与库里 9,527 条已有豆瓣 ID 的视频
  相交后只有 101 条可填（`mac_vod` 共 48,280 行、已有分 2,675 行 → 回填后 2,776）。
  榜单是滚动榜，多跑几天 `ext_source_item` 会累积（按 `provider_code+item_key` 覆盖更新，只增不减），
  相交面随之变宽；但豆瓣不会把冷门老片的分数交出来，别指望填满。
- 回填**只认 `vod_douban_id`**，不校验片名。库里若有错绑的豆瓣 ID，分数会跟着错进——
  开 `overwrite=1` 前先抽样核对若干条。
- 想一次多抓：`sync_limit` 上限 1200，豆瓣 `page_limit` 单页最多 100，
  再多的量靠加频道/标签（如 `热门,最新,经典,可播放,电影`），不是把单页调大。

## 9. 破坏性动作清单（点下去之前先看一眼）

机制层面的全量缺口台账在维护者本机的开发记录里（不随包发布），这一节只给运营视角：

| 位置 | 动作 | 风险 | 现状 |
|---|---|---|---|
| 数据库 → 数据库备份 | `import` / `optimize` / `repair` / `del` | 还原会覆盖数据；`del` 删备份文件 | **GET 就能触发，且无令牌**（[Database.php:160,199,225,251](.../app/admin/controller/Database.php#L160)）；只有 `export`(:64) 是 POST 但也无令牌 |
| 数据库 → 执行SQL语句 | `sql` | 任意 DDL/DML | 有令牌校验（[:270](.../app/admin/controller/Database.php#L270)），**必须 POST** |
| 数据库 → 数据库内容替换 | `rep` | 全表批量改字段 | 有令牌（[:324](.../app/admin/controller/Database.php#L324)） |
| 采集 → 批量播放器管理 | 五个批量动作 | 直接重写 `app/extra/vodplayer.php` | 无方法校验、无令牌（[BatchPlayer.php:25-56](.../app/admin/controller/BatchPlayer.php#L25)） |
| 模版 → 模板管理 | `del` | 删模板文件 | 无 POST/令牌，但路径守卫限制在 `./template` 下（[Template.php:209](.../app/admin/controller/Template.php#L209)） |
| 网站参数 → 站群管理 | 保存 | 重写 `app/extra/domain.php` | POST 但**无令牌**（[Domain.php:12-38](.../app/admin/controller/Domain.php#L12)） |
| 用户 → 管理员 | `del` | 删账号 | 无 POST/令牌；只挡「删自己」（[Admin.php:116-128](.../app/admin/controller/Admin.php#L116)） |
| 计划任务 | `del` / `field` | 删任务、改字段 | 无令牌（[Timming.php:51,64](.../app/admin/controller/Timming.php#L51)），新增/编辑有 |
| URL推送 | 保存 | 写 `maccms.urlsend` | 无令牌（[Urlsend.php:15-17](.../app/admin/controller/Urlsend.php#L15)） |
| 在线升级（不在菜单） | `update/step1` | GET 下载远端 zip 落盘 `app/data/update/` | `Update` 类**跳过权限检查**，源指向官方 v10 通道（[Update.php:15](.../app/admin/controller/Update.php#L15)） |

① 动 `数据库` 组之前先做一份**库外备份**；② 动 `批量播放器管理` / `站群管理` 之前先 `cp app/extra/vodplayer.php`、`domain.php` 到仓库外；
③ 不要给运营账号开 `database` 与 `update` 相关权限（用权限组只勾选需要的动作）。
