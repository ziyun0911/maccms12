## 1. 一页看懂：同一页面有三条出路径

| 模式 | 配置键 | 页面由谁产生 | 谁决定链接长相 |
|---|---|---|---|
| **动态**（出厂默认） | `view.* = 0` | 每次请求由 PHP 渲染 | `mac_url()` 走 ThinkPHP `url()` |
| **伪静态** | `rewrite.status = 1`（+ 可选 `rewrite.route_status`） | 仍是 PHP 渲染，只是 URL 换了皮 | `mac_url()` 去掉 `index.php/` 前缀 |
| **静态** | `view.* = 2 / 3`（详情页 = 2，播放/下载页 = 3） | 后台「生成静态」或计划任务预先写出 HTML 文件 | `mac_url()` 改用 `path.*` 模板拼路径 |

> 三态互不排斥：`view` 是**逐页**开关（首页、地图、RSS、分类、详情、播放…各一个键），可以只把 vod 详情设成静态、列表保持动态。
> ⚠️ **伪静态和静态是两套机制**。选了静态模式（`view.*≥2`）后，该页链接直接按 `path.*` 模板生成，`rewrite` 规则对它不起作用（[app/common.php:2360+](file:///D:/wwwroot/maccms/maccms12/app/common.php#L2360) 的 `switch($model)` 分支里，`view.*==2` 与 `else` 是两条独立代码路径）。

`view.*` 在后台的可选值只有三档（[app/admin/view/system/config_embed_url.html:12-230](file:///D:/wwwroot/maccms/maccms12/app/admin/view/system/config_embed_url.html#L12)）：

| 值 | 界面文案 | 含义 |
|---|---|---|
| `0` | 动态 | 正常渲染 |
| `2` | 静态模式 | 一页一文件（详情、分类列表每页一文件） |
| `3` | 静态每集一页 | 仅 `vod_play` / `vod_down` / `manga_read` / `manga_down` 提供，按「每线路每集」拆文件 |

代码里还认 `4`（播放页「每线路一页」，[app/admin/controller/Make.php:835](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Make.php#L835)）以及 `>=2` 的粗判断（角色页、分集页），但界面没有对应选项——需要就直接改 `app/extra/maccms.php`。
`view.search` / `view.vod_show` / `view.art_show` / `view.manga_show` **只有动态一档**（搜索与筛选页本质上是条件查询，不生成静态）。

## 2. 模板目录结构与常量

```
template/
└── default/                  ← 一个模板 = 一个目录（当前只随包提供 default）
    ├── info.ini              ← 模板名/日期/版本，后台模板列表读它（System.php:420）
    ├── html/                 ← 视图根目录（= site.html_dir）
    │   ├── index/ map/ rss/ label/ vod/ art/ actor/ role/ plot/ topic/
    │   ├── manga/ website/ live/ search/ special/ user/ gbook/ comment/
    │   ├── public/           ← 头尾、弹窗、错误页、分页条（21 个文件）
    │   ├── ads/              ← 16 个广告位模板
    │   ├── module/           ← 33 个首页/栏目楼层片段
    │   └── widget/           ← 56 个小组件片段
    ├── ads/                  ← site.ads_dir 指向这里，出厂是空目录
    ├── asset/                ← css / js / img / fonts / lottie / pwa / language
    └── images/
```

引导期一次性算出五个常量，全部在 [app/common/middleware/Init.php:87-96](file:///D:/wwwroot/maccms/maccms12/app/common/middleware/Init.php#L87)：

| 常量 | 拼法 | 用途 |
|---|---|---|
| `MAC_PATH` | `site.install_dir` | 站点安装前缀（装在子目录时是 `/子目录/`） |
| `MAC_ROOT_TEMPLATE` | `ROOT_PATH/template/{template_dir}/{html_dir}/` | **磁盘**上的视图根，静态生成读写它 |
| `MAC_PATH_TEMPLATE` | `MAC_PATH/template/{template_dir}/` | **URL** 上的模板根 |
| `MAC_PATH_TPL` | `MAC_PATH_TEMPLATE + {html_dir}/` | URL 上的视图根 |
| `MAC_PATH_ADS` | `MAC_PATH_TEMPLATE + {ads_dir}/` | URL 上的广告目录 |

同一份值同时写进 `$GLOBALS`（`Init.php:98-101`），模板里通过 `$maccms.path` / `$maccms.path_tpl` / `$maccms.path_ads` 取用（[app/common/controller/All.php:268-270](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L268)）。

两个实测口径，别踩：

- **广告位模板不在 `ads_dir` 里**。`{include file="ads/ads_banner1"}` 的相对基准是视图根 `template/default/html/`，所以实际命中的是 `html/ads/ads_banner1.html`；`$maccms.path_ads`（= `template/default/ads/`）在随包模板里**一处引用都没有**（全量 grep 零命中），后台「模板管理 → 广告」列的也是 `template/{dir}/ads/*.js`（[app/admin/controller/Template.php:106-120](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Template.php#L106)）这个空目录。要加 JS 广告位脚本就建在这个 `ads/` 下；要改展示结构就改 `html/ads/*.html`。
- **没有 `__TPL__` / `__STATIC__` 替换**。`config/view.php` 的 `tpl_replace_string` 是空数组（[config/view.php:20](file:///D:/wwwroot/maccms/maccms12/config/view.php#L20)），官方旧模板里常见的 `__TPL__`、`__STATIC__` 在本项目**不会**被替换。用 `$maccms.path_tpl` 和 `$maccms.path + 'static/'`。

## 3. 用哪套模板：PC / 手机 / 多域名的选择链

每次请求在 `Init.php` 里按下面顺序定出 `template_dir`+`html_dir`+`ads_dir`（[Init.php:69-83](file:///D:/wwwroot/maccms/maccms12/app/common/middleware/Init.php#L69)）：

1. **UA 嗅探**：命中 `nokia|sony|...|iphone|wap|mobile|android` 即视为移动设备（`Init.php:70-74`）。这是唯一判据，**不看屏幕宽度**。
2. **域名匹配**：`HTTP_HOST` 去 `app/extra/domain.php` 里找条目（`matchDomain`，`Init.php:200-220`）。找到条目就用条目里的站点参数覆盖全局（`resolveSite`，`Init.php:273-317`）；条目的 `template_dir` 为空或等于 `no` 时回退全局值（`Init.php:295-298`）。
3. **是否走 wap 目录**（`pickTemplate`，[Init.php:238-266](file:///D:/wwwroot/maccms/maccms12/app/common/middleware/Init.php#L238)）——只有第 1 步命中移动设备才可能进 wap：

| `site.mob_status` | 无域名条目时 | 有域名条目时 |
|---|---|---|
| `0` 关闭 | 始终 PC 模板 | 始终 PC 模板 |
| `1` 按 wap 域名 | `HTTP_HOST === site_wapurl` 才 wap | 该条目本身是 wap 域名才 wap |
| `2` 按设备 | 移动设备即 wap | 条目配了移动模板才 wap |

4. 判定为 wap 时改用 `mob_template_dir` / `mob_html_dir` / `mob_ads_dir`；否则用 `template_dir` / `html_dir` / `ads_dir`。
5. `MAC_MOB` 常量记录结果（`0`/`1`），并且**参与整页缓存键**（见 §9）。

> 出厂 `mob_status='0'` 且 `mob_*` 三键与 PC 三键完全相同（`template/default/html`），所以移动端和 PC 渲染同一套自适应模板。想分开的正确做法：复制 `template/default` → `template/m wap`，再把 `mob_*` 三键指过去，最后把 `mob_status` 设 `1` 或 `2`。

## 4. 控制器 → 模板：三级决定

### 4.1 默认映射

前台视图根是 `template/{tpl}/{html}/`，`auto_rule=1`、`view_suffix='html'`、`view_depr=DIRECTORY_SEPARATOR`（[config/view.php:3-8](file:///D:/wwwroot/maccms/maccms12/config/view.php#L3)）。所以**控制器名=子目录，方法名=文件名**：

```
index.php/vod/detail/id/1   →  app\index\controller\Vod::detail()  →  vod/detail.html
index.php/user/login        →  app\index\controller\User::login()  →  user/login.html
```

前台控制器共 24 个（`app/index/controller/`），其中 `Base`/`Ajax`/`Verify`/`Qrcode`/`Payment`/`Pwa`/`MyError` 不产出页面模板。

### 4.2 分类级覆盖（真正生效的一级）

列表/详情类模板**不写死**，而是先读该分类的设置字段，空则回退默认：

```php
$this->label_fetch( mac_tpl_fetch('vod', $info['type_tpl'], 'type') );
//                                    ↓ 拼出
//                      'vod/' . (type_tpl 为空 ? 'type' : type_tpl)
```

`mac_tpl_fetch()` 全文 4 行（[app/common.php:2162](file:///D:/wwwroot/maccms/maccms12/app/common.php#L2162)），只做「目录 / 模板名（去掉 .html） / 缺省名」的字符串拼接。

| 分类字段 | 覆盖哪一类页面 | 缺省模板 |
|---|---|---|
| `type_tpl` | 分类列表页（vod/art/manga/website/actor 的 `type()`） | `{模块}/type` |
| `type_tpl_list` | 筛选页（`show()`） | `{模块}/show` |
| `type_tpl_detail` | 详情页（`All.php:513/585/664/714/759/820` 赋给 `{模块}_tpl`） | `{模块}/detail` |
| `type_tpl_play` | 播放页 | `{模块}/play` |
| `type_tpl_down` | 下载页 | `{模块}/down` |

字段在 `mac_type` 表上（`show columns from mac_type` 实测），后台「视频分类」编辑页可填（填模板文件名，不带 `.html`，相对于模块子目录）。

### 4.3 缺页兜底（本项目加的，官方没有）

`All::renderFetch()` 在渲染前查文件是否存在（[app/common/controller/All.php:70-104](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L70)），顺序是：

1. 目标模板在当前模板目录存在 → 正常渲染。
2. 不存在，但 **`template/default/html/` 下有同名文件** → 临时把 `view_path` 切到 default、把 `$maccms.path_tpl`/`path_ads` 也改成 default，渲染完后 `finally` 复原。
   → 意味着第三方模板可以只放它改过的页面，其余页面自动借用 default。
3. 两处都没有，且当前模板有 `public/404` → 渲染 `public/404.html`，并置 `$GLOBALS['__tpl_not_found']=true`。
4. 连 `public/404` 都没有 → 交给 ThinkPHP 抛「模板不存在」。

> 第 2 步只在 `ENTRANCE==='index'` 且模板名不含 `@` 时生效（`All.php:72-73`），后台视图（`admin@xxx`）不走这套兜底。

## 5. URL 生成：`mac_url()` 是唯一出口

入口 [app/common.php:2335](file:///D:/wwwroot/maccms/maccms12/app/common.php#L2335)，签名 `mac_url($model, $param=[], $info=[])`；对外是一族便捷函数（`mac_url_vod_detail()`、`mac_url_type()`、`mac_url_vod_play()`… 见 `common.php:3200-3300`）。

处理顺序：

1. **丢掉空参数**、`page` 缺省填 `1`、`page=1` 时清空、`ksort($param)`（`common.php:2336-2348`）——参数顺序稳定，同一页永远生成同一 URL，利于缓存与 SEO。
2. `$GLOBALS['ismake']=='1'` 表示当前在静态生成流程里（`Make::__construct` 设的，[Make.php:15](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Make.php#L15)），影响是否走静态路径分支。
3. `switch($model)` 分派。`$model` 的合法值就是这几种形态：
   `index/index`、`map/index`、`rss/*`、`label/*`、`vod|art|actor|website/show`、`vod/type`、`vod|art|manga|actor|role|plot|topic/detail`、`vod|manga/play`、`vod|manga/down`。
   其余模型名落到框架 `url()`。
4. **静态分支**用 `config.path.*` 当模板串，把 `{id} {en} {page} {type_id} {type_en} {type_pid} {type_pen} {md5} {year} {month} {day} {sid} {nid}` 逐个替换（`common.php:2353-2354`）。
   路径以 `/` 结尾时自动补 `index`（这样 `vodhtml/123/index` → `vodhtml/123/index.html`）。
   `{md5}` = `md5(主键ID)`，只在你启用 ID 混淆时才需要。
5. **动态分支**调 ThinkPHP `url()`，然后按 `rewrite.status` 决定加不加 `index.php/`（`common.php:3060-3090`）：

| `rewrite.status` | `suffix_hide` | 产出样例 |
|---|---|---|
| `0` 关 | — | `/index.php/vod/detail/id/123.html` |
| `1` 开 | `0` | `/voddetail/123.html` |
| `1` 开 | `1` | `/voddetail/123/`（同时把 `-/` `_/` `-.` `_.` 换成 `/`；`show`/`search` 页除外） |

6. **ID 呈现方式**逐模块可配（`rewrite.vod_id` / `art_id` / `type_id` / `topic_id` / `actor_id` / `role_id` / `website_id` / `manga_id`）：

| 值 | 含义 |
|---|---|
| `0` | 自增 ID 明文 |
| `1` | 用拼音/英文标识（`vod_en`、`type_en`…） |
| `2` | `mac_alphaID(id, false, rewrite.encode_len, rewrite.encode_key)` 转成短字符串，可逆 |

`encode_key`（出厂 `abcdefg`）+ `encode_len`（出厂 `6`）一旦有对外收录的链接就**不要再改**，改了全部老链接失效。

### 5.1 `path.*` 可配清单

后台「网站参数 → URL地址配置 → 静态路径设置」可改的 18 项（[config_embed_url.html:235-680](file:///D:/wwwroot/maccms/maccms12/app/admin/view/system/config_embed_url.html#L235)）：

## 6. 路由表与伪静态

### 6.1 `app/index/route/rewrite.php` 是生成物

58 条 `Route::rule(...)`（实测 `grep -c`），由后台保存 URL 配置时机器生成（[app/admin/controller/System.php:674-703](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/System.php#L674)）：

- 输入是表单里 `rewrite[route]` 那个大文本框，每行 `规则 => 目标`，行间以 `\r` 分隔（`explode(chr(13), str_replace(chr(10),'',...))`，`System.php:674`）。
- 生成器同时写死一份 35 项的 `Route::pattern()`（`id/ids/wd/en/state/area/year/...`，`page/tid/mid/rid/pid/sid/nid/uid` 限 `\d+`）。
- 发布页（`site_publish_status`）开关会决定 `sitehome` 与 `publish-<id>` 两条规则是否注入——`PublishPage::mergePublishRoutes()`（[app/common/util/PublishPage.php:429-459](file:///D:/wwwroot/maccms/maccms12/app/common/util/PublishPage.php#L429)），开启时前插缺失项，关闭时删掉同目标的项。
- 生成失败（目录不可写）返回 `lang('write_err_route')`。

**别手改这个文件**：下次保存 URL 配置就整份覆盖。要自定义规则就改后台文本框。
出厂自带的那份**没有**「由后台自动生成」注释头（生成器现在会写这行，见 `System.php:692`），也就是说你第一次保存 URL 配置后文件内容会明显变化，属正常。

### 6.2 路由开着也不影响 PATH_INFO

生效的路由参数来自**配置组 `route`**（[config/route.php:3-11](file:///D:/wwwroot/maccms/maccms12/config/route.php#L3)），框架在 `Route` 构造时把它盖在自带默认值上
（[vendor/topthink/framework/src/think/Route.php:158](file:///D:/wwwroot/maccms/maccms12/vendor/topthink/framework/src/think/Route.php#L158)），实测生效值：

| 键 | 生效值 | 来自 |
|---|---|---|
| `route_complete_match` | `true` | [config/route.php:3](file:///D:/wwwroot/maccms/maccms12/config/route.php#L3)（[config/app.php:27](file:///D:/wwwroot/maccms/maccms12/config/app.php#L27) 写的 `false` 被整组覆盖，不起作用） |
| `url_route_must` | `false` | 两处一致 |
| `url_common_param` | `true` | 框架默认；[config/app.php:26](file:///D:/wwwroot/maccms/maccms12/config/app.php#L26) 的 `false` 全仓无人读取，是死键（见 `90-变更记录.md` §1.5） |
| `action_bind_param` | `'param'` | [config/route.php:10](file:///D:/wwwroot/maccms/maccms12/config/route.php#L10) |

`url_route_must=false` 所以路由文件**始终加载**、命中就用，未命中回落到 `PATH_INFO`；`rewrite.status` 只管「生成的链接长什么样」，**不是**路由开关。
`?s=/vod/detail/id/1` 兼容模式同样可用。

`route_complete_match=true` 是有意的：关掉它以后，带可选变量的规则（如 `actor-<page>`）会前缀匹配到 `actor-detail-...`、`actor-type-...` 这类本不该归它的 URL，把 detail/type 路由劫走。
副作用是新加规则时得写全，不能指望前缀命中。

另有 [route/addons.php](file:///D:/wwwroot/maccms/maccms12/route/addons.php) 三条 `addons/:addon/:controller/:action` → `Dispatcher@run`（经 `app/index/route/addons.php` 二行 require 引入），属插件体系，见 `10-插件与扩展手册.md`。

### 6.3 Web 服务器规则

`说明文档/伪静态规则/` 下四套现成配置，都是「请求的不是真实文件/目录就转进入口」的写法：

| 服务器 | 文件 | 要点 |
|---|---|---|
| Apache | `.htaccess`（示例） | 根目录安装直接复制；子目录要在 `RewriteEngine on` 后补 `RewriteBase /子目录` |
| nginx | `maccms.conf` | `location /` + `if (!-e ...)`，四个入口 `index.php/admin.php/api.php` 都做 `?s=` 兼容；子目录部署要改四条 rewrite 的前缀 |
| IIS 7+ | `web.config` | 含 `requestFiltering` 拦截段 |
| IIS 6 | `httpd.ini` | ISAPI_Rewrite 2.x **没有**可靠的 `[F]`，也没有 requestFiltering，本文件不提供内部文件拦截 |

规则文件里同时带了**内部目录/后缀访问控制**（`说明文档|runtime|vendor|config|app|extend`、隐藏文件、`.md|.sql|.log|.lock|.wpm|.sh|.ps1|.py`、备份后缀 `.bak/.old/.orig`、`composer.json`/`composer.lock`/`think`），并且**都保留了 `/.well-known/`**（HTTPS 证书 HTTP-01 校验）。这一层的完整口径见 `09-安全与权限手册.md §7`。

> 静态后缀若改成 `shtml`，规则文件里写死的 `.html` 也要一起替换；前缀在「静态路径设置」调。
> IIS6 用户：把 `说明文档/` 整个目录移出网站根目录（前台后台运行都不依赖它），代价是后台「文档与手册」页没得读。

## 8. 模板语法速查

引擎 think-template，`{` `}` 起止，标签库 `Maccms` 通过 `taglib_pre_load` 预载（[config/view.php:12-13](file:///D:/wwwroot/maccms/maccms12/config/view.php#L12)）。20 个 `{maccms:xxx}` 标签的参数面在 `05-模板标签手册.md`。

## 9. 模板编译缓存与清理

`config/view.php`：`tpl_cache=true`、`tpl_force=false`、`cache_path = runtime/temp/`（[config/view.php:14-21](file:///D:/wwwroot/maccms/maccms12/config/view.php#L14)）。
模板改动按 mtime 自动重编译，正常不需要干预。以下三种情况必须手动清 `runtime/temp/`：

1. 批量替换/上传模板文件后（尤其 mtime 早于已编译产物的场景）。
2. 切换 `template_dir` / `html_dir` 之后。
3. 出现「同一次请求渲染了另一套模板」的串扰（内置 `php -S` 在并发下会偶发，清缓存即消，历史归档见 `90-变更记录.md`）。

清缓存的正规入口是后台右上角 **`/admin.php/base/_cache_clear`**，它同时清 `runtime/cache`、`runtime/temp`，并把 `app.cache_flag` 换新值（连带让所有列表标签缓存键失效）——口径与细节见 `07-定时任务与运维手册.md §7`。

整页缓存键把「模板身份」也算进去了（[All.php:153](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L153) / `:178`）：

```
{HTTP_HOST}_{MAC_MOB}_{cache_flag}_{内容语言}_{模板名}_{http_build_query(mac_param_url())}
```

所以 PC/wap 两份缓存天然分开，语言分开，刷 `cache_flag` 一次全部作废。前提是 `app.cache_page=1`。

## 10. 后台「模板管理」能做什么

菜单：模板管理（`app/admin/controller/Template.php`，需 `auth.php` 里的对应权限）。

| 页面/动作 | 能力 | 限制（已核到代码） |
|---|---|---|
| `template/index` | 在 `./template/` 目录树里浏览、看大小与 mtime；`?current=1` 跳当前模板视图根，`?label=1`/`?ads=1` 直接进 `label/`、`ads/` | 路径参数先剥掉 `/` `\`，再强制以 `.@template` 开头，且 `.@` 分段 >2 直接判非法（`Template.php:14-25`） |
| `template/info` | **在线编辑** `.html` `.htm` `.js` `.xml` | 白名单外后缀拒绝；内容过 `mac_reg_replace` 黑名单，命中即整份拒绝保存（`Template.php:166-190`） |
| `template/del` | 删文件（可多选） | 只接受 `./template` 前缀路径；⚠️ **不校验任何令牌**，前端就是 `location.href` 的 GET 链接（[app/admin/view/template/index.html:37/75](file:///D:/wwwroot/maccms/maccms12/app/admin/view/template/index.html#L37)） |
| `template/ads` | 列 `template/{dir}/{ads_dir}/*.js` | 出厂那层 `ads/` 是空目录（§2） |
| `template/wizard` | 模板向导静态页 | 无写入 |
| `TplConfig::theme` | 改 `app/extra/mctheme.php`（logo/lottie/favicon/页脚/站点卡片等外观项） | 与模板目录无关，纯配置 |

编辑页黑名单（`Template.php:172`，节选）：`<?`、`php`、`eval`、`assert`、`get/post/request/cookie/session/input/env/config`、`system/exec/passthru/proc`、`base64`、`file`、`preg`、`{:`、`{$`、`{~`…
**副作用**：正常模板里大量存在 `{$obj.xxx}`、`{:mac_url(...)}`、`{include file=…}`（`file` 这个词本身就在黑名单里），因此这些字符在保存时会被替换成 `*` 并直接报「含不合法内容」。实测随包 `template/default/html/*/*.html` 抽 12 个，**11 个过不了**（只有纯静态的 `blurb.html` 能存）。实际上线改模板请**走文件/FTP/Git**，把后台编辑器只当查看器用——这不是配置能绕开的，是 `$filter` 写死在控制器里。

安全面（CSRF 令牌在后台其它动作里的覆盖情况、`del` 缺令牌的处置建议）见 `09-安全与权限手册.md §8`。

## 11. 排障速查

| 现象 | 真因与处置 |
|---|---|
| 改了模板没生效 | `runtime/temp` 的编译产物没跟上 → 后台 `_cache_clear` 或删 `runtime/temp/*` |
| 生成静态提示「浏览模式…」 | 对应 `view.*` 没设成 2/3（§7.3） |
| 生成静态跑一批就停 | 正常：`makesize` 分批 + 前端自动跳转。浏览器被拦弹窗/你自己点了别的页就断了；无人值守用计划任务，但注意 `info` 单次上限 999（§7.4） |
| 静态文件生成了但访问还是动态页 | Web 服务器优先找真实文件。检查目录权限、`path.suffix` 与文件实际后缀、是否生成了 `/index`（应为 `xxx/index.html`） |
| 打开链接 404，`?s=` 能打开 | 伪静态规则没装/装了没生效；或 `rewrite.status=1` 但服务器规则缺 `index.php?s=` 兼容 |
| URL 里还带 `index.php/` | `rewrite.status` 仍是 `0`（§5 步骤 5），不是路由问题 |
| 保存 URL 配置后规则没变化 | 规则文本框按 **`\r`** 分行：浏览器提交 textarea 会把换行归一成 CRLF，所以后台页面里正常敲回车没问题；但**用脚本/接口直接 POST 纯 `\n`** 时，`str_replace(chr(10),'')` 会把所有规则塌成一行、一条都解析不出来（`System.php:674`）。绕过后台写配置时请用 `\r\n` |
| 后台编辑器保存报「不合法内容」 | `{$`/`{:` 撞上黑名单（§10），改用文件方式编辑 |
| 移动端渲染成 PC 模板 | `site.mob_status=0`，或 wap 三键与 PC 三键同值（§3 第 4 步） |
| 第三方模板某些页 500/空白 | 缺页且 default 兜底也没命中（§4.3 第 3 步），补 `public/404.html` 或补该页模板 |
| 漫画详情链接报错/URL 里出现空串 | 出厂缺 `view.manga_detail` 等四键，进「URL地址配置」保存一次（§5.1 警示框） |
| 图片路径出现 `//` 或漏斜杠 | `site.install_dir`（=`MAC_PATH`）与 `static`/`upload` 拼接问题；子目录部署要把 `install_dir` 设成 `/子目录/` |
