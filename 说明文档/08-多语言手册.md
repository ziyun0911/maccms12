# 多语言手册

这册讲 maccms12 的四套彼此独立的语言机制：各自怎么开、改哪里、作用范围到哪，以及改了不生效时该查什么。
关键结论都标了代码位置，可直接打开核对；文件路径均相对站点根目录（本项目 docroot 就是仓库根，链接里以 `.../` 开头，例如 `.../app/common.php`）。

> 最容易混淆的一点：**界面语言**（后台/提示文案）和**内容语言**（同一部影片给不同访客显示不同名称/简介）是两套东西，
> 配置键、存储、切换方式都不同。第三、四层（`mac_tpl_text` 静态短语、`strings_*.properties` 前台短语包）是给模板里
> 写死的中文短语兜底用的，不属于数据库内容。

## 1. 四层机制总览

| 层 | 管什么 | 存在哪里 | 开关（`app/extra/maccms.php`） | 代码入口 |
|---|---|---|---|---|
| ① 界面语言包 | 后台/前台/接口的**框架文案**（`lang('...')`） | `app/lang/{code}.php` + `app/{模块}/lang/{code}.php` | `app.lang`（默认 `zh-cn`，[maccms.php:161](.../app/extra/maccms.php#L161)） | [app/common/middleware/Init.php:139-143](.../app/common/middleware/Init.php#L139)、[app/common/controller/All.php:41-56](.../app/common/controller/All.php#L41) |
| ② 内容多语言 | **每条内容**的可译字段（名称/副标题/简介/正文…） | 数据表 `mac_content_lang`，一行一个 `(类型, ID, 语言)` | `app.content_lang_list`（`\|` 分隔）、`app.content_lang_default`（[maccms.php:133-134](.../app/extra/maccms.php#L133)） | [app/common.php:3706-4195](.../app/common.php#L3706)、[app/common/model/ContentLang.php](.../app/common/model/ContentLang.php) |
| ③ 模板静态短语 | 模板里**写死的**中文短语（栏目名、按钮、会员组名等） | `app/common.php` 内的 `static $map`（34 条） | 无开关：当前语言 = 默认语言时原样返回 | [app/common.php:3815-3869](.../app/common.php#L3815) `mac_tpl_text()`，25 个调用点 |
| ④ 前台短语包 | 前台 JS/模板的**键值文案** | `template/default/asset/language/strings_{ui}.properties`（每包 1351 键） | 无开关：按当前内容语言的 `lang_ui` 选包 | [app/common.php:3871-3905](.../app/common.php#L3871) `mac_front_string()` |

②③④ 都跟着**内容语言**走，而内容语言由访客决定（见 §4.3）；①只由站长在后台设置，与访客无关。

## 2. 语言注册表：加一门语言先要做的事

系统不认识「语言清单」这种配置文件——**`app/lang/` 下每一个 `.php` 就是一门语言**，按文件名当语言代码。
注册表由 [mac_lang_registry()](.../app/common.php#L3751) 在首次调用时用 `glob('app/lang/*.php')` 生成并静态缓存（文件名含 `.bak` 的会被跳过，[app/common.php:3761](.../app/common.php#L3761)）。

每个语言文件**前 4096 字节**里要有这几个元字段，它们是被正则从文件头“读文本”拿到的（[mac_lang_meta_read](.../app/common.php#L3790)，格式必须是 `'键' => '值'`），不是走 `include`：

| 键 | 作用 | 缺失时 |
|---|---|---|
| `lang_name` | 语言自称名（下拉框/切换器显示） | 用大写语言代码 |
| `lang_sort` | 排序（小在前） | `100 + 字母序下标` |
| `lang_flag` | emoji 国旗，雪碧图没有对应格时的回退（[app/common.php:4001](.../app/common.php#L4001)） | 空 |
| `lang_dir` | `ltr`/`rtl` | `ltr` |
| `lang_ui` | **第④层短语包的后缀**，决定读 `strings_{ui}.properties` | 该语言没有短语包 |
| `lang_legacy` | 旧版两字母代码，只写进切换器的 `data-flag-code` 属性（当前 JS 不读，见 §4.3） | 语言代码前两位 |
| `lang_flag_png` | **雪碧图格 id 候选**，逗号分隔多个，按序取第一个在 `app/lang/lang.svg` 里存在的 | 无图片旗标 |

当前随包的 6 门语言（`ls app/lang/`）：

| 代码 | 名称 | sort | ui | 旗标雪碧图格 id 候选 |
|---|---|---|---|---|
| `zh-cn` | 简体中文 | 10 | `zh` | `lang-zh` |
| `zh-tw` | 繁體中文 | 20 | `zh-tw` | `lang-tw,lang-zh-tw` |
| `en-us` | English | 30 | `en` | `lang-en,lang-us` |
| `ja-jp` | 日本語 | 40 | `ja` | `lang-ja,lang-jp` |
| `ko-kr` | 한국어 | 50 | `ko` | `lang-ko` |
| `ru-ru` | Русский | 60 | `ru` | `lang-ru` |

> **旗标取自一张内联雪碧图**：图片旗标不再是 `template/default/images/la/` 下的独立 PNG，而是 [app/lang/lang.svg](.../app/lang/lang.svg)——
> 6 个 `<symbol id="lang-xx" data-cell="lang-xx" viewBox="0 0 36 36">` 拼成的 sprite，根节点 `width="0" height="0"` 且绝对定位，不占版面。
> `app/` 不是 Web 可达目录（`router.php` 的 `$internalDirs` 含 `app`，Apache/nginx/IIS 三层拦截同样 deny），所以**不走 URL、只能内联进 HTML**：
> [mac_lang_flag_svg()](.../app/common.php#L3928) 读原始字节并静态缓存，[mac_lang_flag_sprite()](.../app/common.php#L3938) 每请求**只输出一次**
> （静态 `$emitted`；多个注入点同时命中也只落一份，避免 `id` 重复），模板用 `<svg …><use href="#格id"></use></svg>` 引用，圆形外框由共享的
> `<clipPath id="mac-lang-clip">` 完成。格 id 由 [mac_lang_flag_cell()](.../app/common.php#L3960) 拿 `lang_flag_png` 候选与 sprite 里的 `data-cell`
> 按序取交集命中，[mac_front_lang_list()](.../app/common.php#L3986) 把它写进 `flag` 键；后台页签用 [mac_lang_flag_icon()](.../app/common.php#L3975) 直接输出 16×16 内联 svg。
> 注入点：前台 [head_block_pc.html:106](.../template/default/html/widget/head_block_pc.html#L106)、
> [user/left_nav.html:176](.../template/default/html/user/left_nav.html#L176)、`public/403|404|500.html` 的语言行；
> 后台 13 个 `*/info.html` 的 `content_lang_tab` 容器（如 [app/admin/view/vod/info.html:93](.../app/admin/view/vod/info.html#L93)）。
> **页面上「当前语言」的槽位有两处**：头部切换器自己的 `.lang-img`（服务端直接写死 `href="#格id"`）与两个 `svg.has-lang` 空槽
> （[head_block_pc.html:110](.../template/default/html/widget/head_block_pc.html#L110) 地球图标位、
> [user/left_nav.html:180](.../template/default/html/user/left_nav.html#L180) 移动端会员抽屉的语言行），后者的 `<use href>` 由
> `head-defer-public.js` 在载入和点击时按当前项 `data-flag` 填充；抽屉那一项由 [module-head.js](.../template/default/asset/js/module-head.js)
> 把 `.lang-wrap` **克隆**进 `#macMemberLangDrawer`，雪碧图留在 `#left` 里所以 `<use>` 照样解析得到。
> 槽位早期是一个 `<span class="userli-img has-lang">`，靠 CSS 画不出国旗只会显示 emoji 字母，2026-11-04 改成内联 `<svg>`。
> **emoji 回退那条路径仍然有效且必须留着**：`app/lang/lang.svg` 缺失、或某门语言没有对应格时 `flag` 为空，
> 模板自动改用 emoji（[head_block_pc.html:117](.../template/default/html/widget/head_block_pc.html#L117)），后台页签退化成纯文本语言代码。这不是 bug。
> 历史注记：原先是 `la/` 目录里 6 张 PNG 逐个 `is_file` 探测（`lang-us.png` 曾与 `lang-en.png` 逐字节相同，2026-11-03 目录折叠时删掉那份副本）。
> 2026-11-04 先折叠成一张按百分比定位的 CSS 雪碧图，同日再改成现在的内联 symbol 版；新增的四张 PNG 与第一版 `la/lang.svg` 均已归档到仓库外的
> `_bak_legacy_20261025/`。`lang-zh.png`、`lang-en.png` 两张**仍在工作树里且被 git 跟踪**，但探测逻辑已删除、无任何代码引用，是否清退待站长裁定。

新增一门语言的完整动作：
1. 复制一份 `app/lang/zh-cn.php` 改名成 `xx-yy.php`，改掉头部 7 个元字段（保持在前 4096 字节内、单引号写法）。
2. 后台「网站参数 → 前台内容语言」勾选 `xx-yy`（写进 `app.content_lang_list`），必要时把默认语言也换掉。
3. 想要第④层生效，补 `template/default/asset/language/strings_{lang_ui}.properties`；不补则该语言前台短语回落到模板里写死的中文。
4. 想要图片旗标，往 `app/lang/lang.svg` 加一格 `<symbol id="lang-xx" data-cell="lang-xx" viewBox="0 0 36 36">…</symbol>`，再把该 id 写进语言头部
   的 `lang_flag_png`（两者 id 对不上就自动退回 emoji）。

界面语言包本身：**建议不改公共包**，改文案请自建 `app/{模块}/lang/{语言}.php` 放同名 key——模块包会在公共包之后
`Lang::load()` 覆盖（[app/common/controller/All.php:52-55](.../app/common/controller/All.php#L52)）。
覆盖机制还在，但**当前仓库不再随包任何模块级语言包**：原先的 `app/{admin,api,index,install}/lang/zh-cn.php`
四份文件各 18 字节、`return [];` 里 0 个 key，既不覆盖任何东西也只是每次请求空加载一次，已于 2026-11-02 删除。
框架用 `glob(应用目录 . 'lang/{语言}.*')` 取模块包，目录或文件不存在时静默跳过，要自定义就整条路径自己建。
其它语言在模块层没有覆盖，未命中的 key 会原样显示 key 名。

## 3. ① 界面语言（后台与提示文案）

- 决定值：`app.lang`。安装器写入，后台可改：`admin.php/system/configlang?lang=xx`，
  只接受注册表里的代码，落盘到 `app/extra/maccms.php`（[app/admin/controller/System.php:2295-2311](.../app/admin/controller/System.php#L2295)）。
- 生效链路：请求开始 → 中间件把 `app.lang` 同步给框架（`Config default_lang` + `Lang::setLangSet`，
  [Init.php:139-143](.../app/common/middleware/Init.php#L139)）→ 控制器基类再 `switchLangSet` 并加载
  `app/lang/{lang}.php`（[All.php:41-56](.../app/common/controller/All.php#L41)）。
- 与内容语言**互不影响**：把界面切成 `en-us` 不会让前台内容变英文；反之亦然。

## 4. ② 内容多语言（主力机制）

### 4.1 存储

表 `mac_content_lang`（模型 [ContentLang](.../app/common/model/ContentLang.php#L9)，实际表名带前缀 `mac_`）：

| 列 | 说明 |
|---|---|
| `content_type` | `vod / art / manga / actor / website / live / type / topic / link / task`（与 [mac_content_lang_fields](.../app/common.php#L3706) 的键一致） |
| `content_id` | 主表记录 ID |
| `lang_code` | 语言代码（注册表代码） |
| `data` | **一段 JSON**，只存被翻译的字段；允许不完整 |
| `source` | `manual`（后台手填）或自动翻译写入 |
| `status` | 保存时传入（后台手填路径传 `1`，[app/admin/controller/Vod.php:542](.../app/admin/controller/Vod.php#L542)） |
| `update_time` | UNIX 秒 |

唯一键 `uniq_item_lang`，写入走 upsert（[ContentLang.php:102](.../app/common/model/ContentLang.php#L102)）；读取异常一律吞掉返回空数组，
所以「表还没建」的老站不会 500，只是没有译文（[ContentLang.php:35-37](.../app/common/model/ContentLang.php#L35)、[:101-107](.../app/common/model/ContentLang.php#L101) 记 error 日志）。

本机现状（2026-10-26 清库后）：`mac_content_lang` 共 255 行 = `type` 250（50 个分类 × 5 门非默认语言）+ `vod` 5。

`art/manga/actor/website/type/topic` 的短字段走 `mac_filter_xss()`，正文类（`vod_content`、`art_content` 等）不在名单内、原样存。

### 4.3 访客语言怎么定下来

`app/index/controller/Base.php` 构造时调用 [init_content_lang()](.../app/index/controller/Base.php#L23)，
API 模块同样在 [app/api/controller/Base.php:13](.../app/api/controller/Base.php#L13)。判定顺序在
[mac_get_content_lang()](.../app/common.php#L4053)：

1. `?lang=xx-yy`（GET，优先级最高）
2. Cookie `mac_content_lang`
3. `Accept-Language` 的第一个子标签
4. `app.content_lang_default`

候选值不是「逐字命中清单才算数」，进默认值之前要先过一遍 [mac_content_lang_resolve()](.../app/common.php#L4011)：

| 步骤 | 规则 | 实测例子（清单 = 6 门语言，默认 `zh-cn`） |
|---|---|---|
| 1 精确 | 小写 + trim 后等于清单某项 | `ja-jp` → `ja-jp` |
| 2 地区段 | 把清单每项按 `xx-yy` 拆成「语言段 / 地区段」两张表，候选等于**地区段**即命中 | `jp` → `ja-jp`、`tw` → `zh-tw`、`us` → `en-us`、`kr` → `ko-kr`、`ru` → `ru-ru` |
| 3 尾段回退 | 候选自己按 `-_` 拆段，**从右往左**找地区段表 | `zh-hant-tw` → `tw` → `zh-tw`、`en-gb` → `gb` 不在表 → 落第 4 步 |
| 4 语言段 | 用候选的第一段查语言段表 | `ja` → `ja-jp`、`en-gb` 的 `en` → `en-us`、`zh` → `zh-cn` |
| 5 平票 | 一个段对应多项时，默认语言在候选项里就选默认，否则选清单第一项 | `cn` 只映射 `zh-cn`；若清单里同时有 `zh-cn/zh-hk` 且默认 `zh-hk`，`cn` 就给 `zh-hk` |
| 6 落空 | 返回空串 → 用 `app.content_lang_default`，不报错 | `fr`、`de` → `zh-cn` |

这套解析对 GET、Cookie、`Accept-Language` **三层候选一视同仁**：Cookie 里存着 `jp` 也会被认成 `ja-jp`（2026-11-04 之前只认全码，两字母/三字母写法一律静默回默认语言）。
只有第 1 种来源（`?lang=`）会写 Cookie，写入的是**解析后的全码**，有效期 30 天、路径 `/`（[app/common.php:4080-4085](.../app/common.php#L4080)）。

`lang_legacy`（两字母旧代码）**不参与**这套解析，它只被写进切换器的 `data-flag-code` 属性，而当前 JS 已不读该属性；
且随包的 6 份语言头里 5 份写着 `'lang_legacy' => 'cn'`（只有 `en-us` 是 `en`），属残留数据，别把它当别名表用。

前台一次点击**有两个 handler**，顺序固定（[static/js/mac-theme-runtime.js:42-64](.../static/js/mac-theme-runtime.js#L42) 是 document 级，先于 jQuery 委托跑）：

1. `mac-theme-runtime.js`：`closest('[data-mac-lang]')` → `preventDefault()` → `normalize()`（只剩 `zh|cn→zh-cn`、`en→en-us`，是服务端的冗余前置）
   → 与当前 Cookie 相同就**什么都不做**（避免无意义重载）→ 写 Cookie → 跳转。
   跳转方式分两种：URL 里带 `?lang=` 时**改写查询串**再 `location.replace()`，否则 `location.reload()`。
   原因是 GET 优先级高于 Cookie——在 `?lang=zh-cn` 这种地址上只改 Cookie 再重载，会被服务端弹回原语言（[static/js/mac-theme-runtime.js:34-40](.../static/js/mac-theme-runtime.js#L34)）。
2. `head-defer-public.js` 的 `.lang` 委托：把当前项的 `data-flag` 灌进页面上所有 `svg.has-lang` 的 `<use href>`（**国旗槽位**，见 §2），
   无旗标格时显示 emoji 并切 `.no-lang`；再按 `en-us` 切 `.actor_lang_en/zh`、写 `localStorage.lang`/`langSrc`、重读短语包、移除 `.lang-wrap-body`。

> 已知边界：
> - `content_lang_list` 为空时函数直接返回默认语言，**不写 Cookie**（[app/common.php:4057-4058](.../app/common.php#L4057)）。
> - `Accept-Language` 只取**第一个**子标签（`preg_match('/^([a-z\d\-]+)/i')`，[app/common.php:4072-4074](.../app/common.php#L4072)），
>   **不解析 q 值、不顺延到第二选择**：浏览器首选语言没启用时不会退回它后面那门语言。刻意保留（改了会改变访客可见语言），需要就自己加权重遍历。
> - `?lang[]`、`?lang[a]=1` 这类**数组型入参**在 [app/common.php:4066](.../app/common.php#L4066) 由 `is_string()` 挡掉，
>   `mac_param_url()` 也统一把数组压成空串（[app/common.php:1945-1950](.../app/common.php#L1945)）。两处都是防 `strtolower()`/`trim()` 收到数组直接 TypeError 全站 500。
> - `langFile()` 里 `0/1/''/null` 会被 `resolve()` 折回 `window.maccms.content_lang`（服务端口径），所以 `public-home-stack.js`
>   等 4 处 `loadProperties(localStorage.getItem('lang'))` 的次级调用**不可能**覆盖服务端语言；代价是 `cache:false` 会多请求一次 `strings_*.properties`。
> - 跨页签不同步照旧：`storage` 监听只在 `localStorage['mac_content_lang']` 变化时触发，而 JS 写的是 `lang`/`langSrc`（见 §7）。

启用清单的读法：`app.content_lang_list` 用 `|` 分隔，再和注册表代码取交集（[mac_content_lang_allow_list](.../app/common.php#L3919)）；
默认语言总被隐式包含在可切换集合里（保存配置的前端会把默认项强制勾上，[app/admin/view/system/config.html:1504-1508](.../app/admin/view/system/config.html#L1504)）。

### 4.4 覆盖发生在哪些数据入口

译文不是全局魔法，只在**具体入口**上覆盖，这是「为什么详情页变了、列表页没变」的原因：

| 入口 | 是否覆盖 | 证据 |
|---|---|---|
| 各内容模型 `infoData()`（详情/编辑回显） | ✅ | [app/common/model/Vod.php:696](.../app/common/model/Vod.php#L696)、[Type.php:229](.../app/common/model/Type.php#L229) 调 [mac_content_lang_overlay](.../app/common.php#L4090) |
| 分类导航/分类页（`type_list`/`type_tree` 缓存） | ✅ 每个已启用语言各存一份变体 | [Type.php:373-381](.../app/common/model/Type.php#L373)、[:429-441](.../app/common/model/Type.php#L429) |
| 详情页里的播放线路 / 服务器组 / 播放器 / 下载器名称与提示 | ✅ 译文就近放在 `app/extra/vod{player,downer,server}.php` 各条目的 `content_lang[语言]` 里，不落库 | [app/common/model/Vod.php:713-716](.../app/common/model/Vod.php#L713) 调 [mac_config_lang_overlay](.../app/common.php#L4179) |
| `{maccms:vod}` 等列表标签、站内搜索、聚合接口（`listData()`） | ❌ 显示默认语言原文 | 标签侧未见 overlay 调用（[app/common/model/Vod.php:139-175](.../app/common/model/Vod.php#L139) 键提取段无 overlay） |
| 直播分类名、会员组名、站点名等模板写死文案 | ✅ 走 ③ `mac_tpl_text()` | [app/api/controller/Live.php:31](.../app/api/controller/Live.php#L31)、[app/api/controller/User.php:785](.../app/api/controller/User.php#L785)、[All.php:267](.../app/common/controller/All.php#L267) |
| 后台「生成静态」产出的 `index.html` / 详情静态页 | ❌ 生成在后台入口进行，`ContentLang::getCurrent()` 恒为默认语言；`Make.php` 里没有任何 `content_lang` 处理 | `grep content_lang app/admin/controller/Make.php` → 0 命中 |

整页 HTML 缓存的 key 已带内容语言标记（`..._cache_flag_{语言}_{模板}_{参数}`，[All.php:153](.../app/common/controller/All.php#L153)、[:178](.../app/common/controller/All.php#L178)），
所以各语言的整页缓存互不串台。

### 4.5 后台怎么填译文

- 入口：任一内容编辑页（`vod/art/manga/topic/actor/website/live/type/link/task` + `vodplayer/voddowner/vodserver` 的 `info/index` 页）。
- 条件：`content_lang_enabled` 数量 > 1 才出现语言分页签（[app/admin/controller/Vod.php:584-595](.../app/admin/controller/Vod.php#L584)，模板判据 `$content_lang_multi`，[app/admin/view/vod/info.html:92-101](.../app/admin/view/vod/info.html#L92)）。
- 表单口径：默认语言那一页 **`name` 属性保持原样**（`vod_name`…），老的采集/导入完全不受影响；其它语言页字段名是
  `content_lang[{语言}][{字段}]`（[app/admin/view/vod/info.html:118-120](.../app/admin/view/vod/info.html#L118)），与主表单一次提交。
- 保存：控制器把 `content_lang` 从主参数里剥出来，逐语言 `saveFields(..., 'manual', 1)`（[app/admin/controller/Vod.php:529-542](.../app/admin/controller/Vod.php#L529)）。
- 回显标记：非默认语言页顶上有「已译/未译」徽章（[app/admin/view/vod/info.html:106-110](.../app/admin/view/vod/info.html#L106)）。
- 删除内容时译文**级联删除**：各模型的删除路径都调 [ContentLang::deleteByContent()](.../app/common/model/ContentLang.php#L110)
  （`Actor.php:521`、`Art.php:644`、`Manga.php:640`、`Topic.php:494`、`Type.php:315`、`Link.php:134`、`Live.php:85`、`Task.php:74`）。
  用 SQL 直接删主表记录不会走到这里，会留下孤儿行——清理办法见 §7。

## 5. ③ 模板静态短语（`mac_tpl_text`）

模板里写死的中文短语（`电影`、`更多`、`换一换`、`VIP会员`、默认 SEO 标题等）由
[mac_tpl_text()](.../app/common.php#L3815) 按当前内容语言查一张 **34 条的静态映射表**
（[app/common.php:3826-3866](.../app/common.php#L3826)），命中就替换，不命中原样返回；当前语言 = 默认语言时整个函数直通。

用法（模板里）：`{:mac_tpl_text('更多')}`、`{:mac_tpl_text($vo['group_name'])}`。全站 25 个调用点，集中在
`template/default/html/module/index_theme_vars.html`、`user/*.html`、直播 API 与会员 API。

加一条短语：直接在 `$map` 里追加 `'中文' => ['zh-tw'=>..., 'en-us'=>..., ...]`；键必须与传入文本**逐字相等**（区分全角/空格）。
这是纯代码扩展点，没有后台界面。

## 6. ④ 前台短语包（`strings_{ui}.properties`）

- 文件：`template/default/asset/language/strings_{ui}.properties`，`ui` 取自语言包的 `lang_ui`
  （[app/common.php:3882](.../app/common.php#L3882)）。当前 6 个文件、每个 1351 个键，六种语言一一对应。
- 语法：`key=value` 一行一条，`#` / `!` 开头行与空行跳过，键值两端空白自动去掉（[app/common.php:3887-3899](.../app/common.php#L3887)）；同语言文件首次读取后进程内静态缓存。
- 用法：模板 `{:mac_front_string('string_foot_email', '联系邮箱')}` —— 第二个参数是**找不到键时的兜底原文**，所以缺键不会开天窗。
  前台 40 个模板文件在用（`public/close.html`、`public/msg.html`、`user/*.html` 等）。
- 前端侧还有 `data-title="string_xxx"` 形态的键挂在元素上（[template/default/html/widget/head_block_pc.html:107](.../template/default/html/widget/head_block_pc.html#L107)），
  由 JS 短语层消费。

加一门语言的短语包 = 新建 `strings_{新 lang_ui}.properties` 并补齐 1351 键；漏键只回退原文，不报错。

## 7. 运维：改完不生效的排查顺序

| 症状 | 原因 | 处理 |
|---|---|---|
| 前台详情页切换语言后不变 | 内容语言由 `?lang=`/Cookie/`Accept-Language` 决定，Cookie 里还留着旧值 | 清 `mac_content_lang` Cookie，或带 `?lang=xx-yy` 访问一次 |
| **带 `?lang=` 的地址上点切换器又弹回原语言** | 服务端 GET 优先级高于 Cookie，只改 Cookie 再 `reload()` 必然被 GET 值盖掉 | 已修：`mac-theme-runtime.js` 检测到查询串里有 `lang=` 时改写它并 `location.replace()`（[static/js/mac-theme-runtime.js:34-40](.../static/js/mac-theme-runtime.js#L34)）。若你自改版还走 `reload()`，照这条改 |
| **`?lang=jp` / `?lang=zh-Hant-TW` / `Accept-Language: ko` 回落默认语言** | 旧解析只认清单里的全码 | 已修：`mac_content_lang_resolve()` 按地区段/语言段两级别名匹配（[app/common.php:4011-4051](.../app/common.php#L4011)，规则见 §4.3） |
| **`?lang[]=x` 让全站 500** | 数组入参喂给 `strtolower()`/`trim()` 抛 TypeError | 已修：`is_string()` 前置（[app/common.php:4066](.../app/common.php#L4066)）+ `mac_param_url()` 把数组型入参压成空串（[app/common.php:1945-1950](.../app/common.php#L1945)） |
| **移动端会员抽屉的语言行显示 emoji 字母而不是国旗** | 槽位曾是空 `<span>`，画不出旗标 | 已修：改成 `svg.has-lang` 内联槽位（[template/default/html/user/left_nav.html:180](.../template/default/html/user/left_nav.html#L180)），由 JS 填 `<use href>` |
| **分类名/分类导航**改了库或改了译文后仍显示旧的 | 分类走 `type_list`/`type_tree` 核心缓存，键前缀是 `app.cache_flag`（[Type.php:403](.../app/common/model/Type.php#L403)，flag 取自 [maccms.php:98](.../app/extra/maccms.php#L98)） | 后台「清除缓存」，或直接删 `runtime/cache` 下 `{flag}_type_list`、`{flag}_{语言}_type_list` 等键；改 `cache_flag` 可一次性让全部核心缓存失效 |
| 列表标签（`{maccms:vod}`）里名称不变 | 列表标签本来就不做译文覆盖，且列表缓存键是查询条件哈希，写数据不会失效 | 见 `05-模板标签手册.md` §缓存；等 `cache_time` 过期或改 `cache_flag` |
| 整页缓存串语言 | 若曾手改过缓存 key 逻辑才会发生；原生 key 已带语言 | 确认 [All.php:153](.../app/common/controller/All.php#L153) 未被改动 |
| 静态首页/WAP 首页没有多语言 | 生成静态在后台入口，语言恒为默认（`Make.php` 无 `content_lang` 逻辑） | 多语言站请用动态页 + 整页缓存；静态首页只服务默认语言 |
| `?lang=ja-jp` 后前台短语仍是中文 | 该语言 `lang_ui` 对应的 `strings_ja.properties` 缺键，或语言包头部没写 `lang_ui` | 补 properties；核对 `app/lang/ja-jp.php` 前 4096 字节内的 `'lang_ui' => 'ja'` |
| 切换器没有国旗 | `app/lang/lang.svg` 没随包部署，或该语言 `lang_flag_png` 候选在 sprite 里没有同名 `data-cell` 格 | 属预期，自动改用 emoji；要图片就按 §2 加一格并把 id 写进候选。先在页面里数一遍 `symbol` 个数与 `use` 是否有悬空 `href` |
| 跨页签切换语言不同步 | `mac-theme-runtime.js` 监听的是 `storage`（localStorage）事件且只看 `mac_content_lang` 这个键，而切换器写的是 **cookie**（localStorage 里写的是 `lang`/`langSrc`），该监听实际不会被触发（[static/js/mac-theme-runtime.js:66-74](.../static/js/mac-theme-runtime.js#L66)） | 现状如此；刷新其它页签即可 |
| 改了切换器 JS / CSS 但浏览器还是旧行为 | 这两个文件**不进 `front:bundle`**，模板里挂的是字面量 `?v=`（[template/default/html/public/include.html:18-19](.../template/default/html/public/include.html#L18)），不改版本号就命中缓存 | 每次改完把 `?v=` 一起抬；`head-defer-public.js`、`user-head-early.css` 同理 |
| `mac_content_lang` 里有孤儿行（主记录已删） | 用 SQL 直删主表绕过级联删除 | 按 `content_type`+`content_id` 反查主表后删除孤儿；先备份（本机备份放 docroot 外的 `D:/wwwroot/maccms/_db_backup/`）。2026-10-26 已清过一次：删 165 行 `type` 孤儿译文 |

清理前定位孤儿的 SQL（只读，先看数量再删）：

```sql
SELECT cl.content_type, cl.content_id, cl.lang_code
FROM mac_content_lang cl
LEFT JOIN mac_type t ON t.type_id = cl.content_id
WHERE cl.content_type = 'type' AND t.type_id IS NULL;
```

## 8. 自动翻译（可选）

后台非默认语言字段旁的「自动翻译」按钮，只在 `mac_content_translate_available()` 为真时渲染
（[app/common.php:4119-4125](.../app/common.php#L4119)）。它有两条来源，任一可用即显示：

1. **内置翻译通道**：[app/common/util/Translate.php](.../app/common/util/Translate.php)，支持 `baidu` / `tencent` / `deepl` / `openai` 四种，
   凭证配在 `app/extra/translate.php`（该文件被 gitignore，**不要提交、不要在文档里写值**）。`available()` 按渠道检查必填凭证键（[Translate.php:38-55](.../app/common/util/Translate.php#L38)）；
   语言代码由 `mapLang()` 映射到各家写法（[Translate.php:57-79](.../app/common/util/Translate.php#L57)），`deepl` 的 `zh-cn`/`zh-tw` 都归 `ZH`。
2. **插件钩子** `content_translate`：装了注册该钩子的插件即生效，约定见 [app/common.php:4127-4153](.../app/common.php#L4127)
   （入参 `text/from/to/context`，返回字符串表示已处理，返回 `null` 交给下一个）。

后台动作 `*/contentLangTranslate`（如 [app/admin/controller/Vod.php:605-615](.../app/admin/controller/Vod.php#L605)）在调用前后受
**按管理员限流**：默认 40 次/分钟、600 次/小时（[mac_content_translate_rate_limit](.../app/common.php#L4155)），
计数落在核心缓存；没有可用翻译通道时**不计数、直接放行**。两者都不可用时按钮不显示，全程手填也能用。

> 翻译请求走 cURL 且 `SSL_VERIFYPEER/HOST` 关闭（[Translate.php:220-221](.../app/common/util/Translate.php#L220)、[:239-240](.../app/common/util/Translate.php#L239)）。
> 这是**已知取舍**（老环境缺 CA 包），意味着译文通道不校验证书。生产环境请自行评估，别把敏感字段拿去翻译。
