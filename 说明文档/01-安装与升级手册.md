## 2. 运行要求

### 2.1 版本

| 项 | 要求 | 依据 |
|---|---|---|
| PHP | **≥ 8.0.2 硬卡**（向导入口直接 die）；环境检测页按 `8.0` 比对 | `install.php:6-8`、[app/install/controller/Index.php:474-479](file:///D:/wwwroot/maccms/maccms12/app/install/controller/Index.php#L474) |
| 实际开发/验证所用 | PHP 8.3.8 + ThinkPHP 8.1.4 | `composer.lock` |
| MySQL | 5.6+（本项目在 5.7.38 验证；`install.sql` 依赖 InnoDB + `utf8mb4`） | `install.sql` |
| Web 服务器 | Apache / nginx / IIS7+ / `php -S`；都能跑，差别只在伪静态与访问控制文件 | `说明文档/伪静态规则/` |

### 2.2 扩展与函数

向导第 2 步逐项检测，**任何一项不支持都会置 `session('install_error')`，第 3/4/5 步直接拒绝继续**（[Index.php:36-53](file:///D:/wwwroot/maccms/maccms12/app/install/controller/Index.php#L36)）：

| 检测项 | 类型 | 缺了会怎样（真实运行影响） |
|---|---|---|
| `pdo` | 类 | 无法连库 |
| `pdo_mysql` | 模块 | 无法连 MySQL |
| `zip` | 模块 | **仅影响 xlsx 导入导出与插件安装包**：`BulkTableIo`、`AddonSecureInstaller`、`Base::base_export` 都用 `class_exists('ZipArchive')` 判空后明确报错或降级（[app/admin/controller/Database.php](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Database.php)、[app/common/util/BulkTableIo.php:137](file:///D:/wwwroot/maccms/maccms12/app/common/util/BulkTableIo.php#L137)）。**在线升级不用它**——升级包解压走随仓自带的 `app/common/util/PclZip.php`。 |
| `fileinfo` | 模块 | 上传类型嗅探失效 |
| `curl` | 模块 | 采集、站外入库、自动翻译、图片中转全部失效 |
| `xml` | 模块 | RSS/Sitemap 解析 |
| `file_get_contents` / `mb_strlen` | 函数 | 模板读取 / 中文截断 |

⚠️ **`zip` 这一项偏严**。装了 `zip` 才装得下去，但你也可以先用带 zip 的 PHP 装完，再换回不带 zip 的环境跑（只是后台「批量导入导出 xlsx」和「插件安装」会给出「需要 ZipArchive」的错）。
本机验证环境（`D:/BtSoft/Btsoft/php/83`）实测 `extension_loaded('zip') === false`，直接跑网页向导会卡在第 2 步——**这不是程序坏了，是环境项没过**。

🐞 **环境检测在非中文向导语言下漏检 `pdo`**（[Index.php:531](file:///D:/wwwroot/maccms/maccms12/app/install/controller/Index.php#L531)）：判定条件第一项写死了中文 `'类' == $v[3]`，而 `$v[3]` 是 `lang('install/class')`；选英文/日文时它等于 `Class`，三项比较全落空，`pdo` 那一行**永远不会被判不支持**。用非中文装完请自己确认 `php -m | grep -i pdo`。

## 3. 五步安装

访问 `http://你的域名/install.php`。

| 步 | URL | 界面 | 做的事 |
|---|---|---|---|
| 1 | `/install.php`（step 0） | `index.html` | 选语言（候选来自 `mac_lang_registry()`，6 种），存进 `session('lang')`，后续所有向导文案用它 |
| 2 | `/install.php/index/step/2` | `step2.html` | 环境检测（§2.2/2.3） |
| 3 | `/install.php/index/step/3` | `step3.html` | 显示安装子目录（取 `SCRIPT_NAME` 的目录部分），同一页里先填数据库、再填站点与管理员 |
| 4 | `POST /install.php/index/step/4` | — | 校验并连库、生成 `config/database.php`、必要时建库 |
| 5 | `POST /install.php/index/step/5` | — | 写配置、建表、灌数据、建管理员、写 `install.lock` |

`install.php` 装完会拒绝第二次进入：

```
如需重新安装请删除【To re install, please remove】 >>> /app/data/install/install.lock
```
（[install.php:34-36](file:///D:/wwwroot/maccms/maccms12/install.php#L34)）锁文件内容是安装时间。**删掉它就能重装**——务必先备份数据库，`step/5` 会重跑 `install.sql`。

### 3.1 第 4 步：数据库参数校验

| 字段 | 规则 |
|---|---|
| `hostname` `database` `username` | 必填 |
| `hostport` | 必填 + 数字 |
| `prefix` | 必填 + 正则 `^[a-z0-9]{1,20}[_]{1}` —— **小写字母数字 1~20 位，且必须以单个 `_` 结尾**，例：`mac_`。写成 `mac`、`MAC_`、`a_b_` 都会被拒 |
| `cover` | 必填，`0`/`1`（是否覆盖同名库） |

流程（[Index.php:91-149](file:///D:/wwwroot/maccms/maccms12/app/install/controller/Index.php#L91)）：

1. `config/database.php` 不可写 → 直接报错返回。
2. 用 PDO 试连（`ATTR_TIMEOUT=5`、`ERRMODE_EXCEPTION`、关闭模拟预处理）。失败把 PDO 异常消息原样显示——**注意这条消息会回显到浏览器**，别在公共场合截带账号的图。
3. 生成并覆写 `config/database.php`（模板在 `Index.php:559-`，`charset=utf8mb4`、`debug=false`、集中式、不读写分离）。
4. `include` 刚写入的文件并 `Config::set(..., 'database')` 让本请求立刻用新配置——这一步在开了 `opcache.enable_cli` 的环境里可能读到旧字节码，Web 端不受影响。
5. `cover=0` 且库里已有同名 schema → 提示「数据库已存在」；否则 `CREATE DATABASE IF NOT EXISTS ... DEFAULT CHARACTER SET utf8mb4`（库名做了反引号转义）。

### 3.2 第 5 步：写配置 + 建表 + 灌数据

| 顺序 | 动作 | 关键点 |
|---|---|---|
| 1 | 校验 `account`（`alphaNum`）、`password`（`length:6,20`） | 只允许字母数字，密码 6~20 位 |
| 2 | 重置 `app.cache_flag = substr(md5(time()),0,10)` | 一次性作废旧缓存 |
| 3 | `app.lang = session('lang')` | 后台界面语言跟随安装语言 |
| 4 | `api.vod.status=0`、`api.art.status=0`、`interface.status=0` | **视频/文章数据接口与站外入库出厂是关的** |
| 5 | `interface.pass = mac_get_rndstr(16)`、`api_jwt_secret = mac_get_rndstr(32)`（已有且 ≥32 位则保留）、`monitor.cron_token`（<16 位则重生成 32 位） | 三个随机密钥**每次安装都不同**；本手册只写键名，值请自行抄在密码管理器 |
| 6 | 补齐 `ai_search` 防滥用 5 项、`analytics` 6 项、`ai_content` 10 项、`monitor` 33 项、`push` 4 项默认值 | 全部是 `isset` 才填，不覆盖你已有的值 |
| 7 | `mac_arr2file('app/extra/maccms.php', $config_new)` | 整份覆写 |
| 8 | 幂等补 10 条计划任务定义到 `app/extra/timming.php`，写完 `chmod 0644` + `opcache_invalidate` | 10 条是：`analytics_hour`、`analytics_day`、`notify_vip_expire`、`vod_publish`、`content_ai_annotate`、`content_quality`、`content_quality_art`、`user_profile`、`user_access_purge`、`push_broadcast`。前 4 条与后 6 条的 status 见 [Index.php:352-403](file:///D:/wwwroot/maccms/maccms12/app/install/controller/Index.php#L352)（`notify_vip_expire`、AI 标注、质量分、用户画像出厂为 `0`）。口径详见 `07-定时任务与运维手册.md §4` |
| 9 | 逐条执行 `app/install/sql/install.sql` | **80 张表**（实测 `grep -c 'CREATE TABLE'`），前缀替换靠 `mac_parse_sql($sql, 0, ['mac_' => $prefix])` |
| 10 | 勾了「创建初始数据」才执行 `app/install/sql/initdata.sql` | 50 条 `mac_type` 分类 + **1 条 250 行的 `mac_content_lang` 多值 INSERT**（`content_type='type'`，只译 `type_name`，5 种非默认语言 × 50 个分类），带 `ON DUPLICATE KEY UPDATE ... JSON_SET(...)` 合并写 |
| 11 | `(new Admin())->saveData(['admin_name'=>..,'admin_pwd'=>..,'admin_status'=>1])` | 密码经 `mac_hash_password_for_column()`；`admin_id` 空走 insert 分支 |
| 12 | 写 `app/data/install/install.lock`，返回跳转 `admin.php` | — |

> 🐞 **第 11 步的失败判断是失效的**。源码是 `if (!$res['code'] > 1)`（[Index.php:460](file:///D:/wwwroot/maccms/maccms12/app/install/controller/Index.php#L460)），PHP 会先算 `!$res['code']` 得 `false`，再比 `false > 1` → 恒为 `false`。管理员创建失败时**照样写 lock、照样报安装成功**。
> **装完立刻自查**：`SELECT admin_id, admin_name, admin_status FROM mac_admin;` 应有一行且 `admin_status=1`。空表就说明第 11 步失败了，用 §3.3 的办法手工补一个账号。

### 3.3 没有管理员账号时的补救

表里有 `mac_admin` 结构但没有可用行时，直接插一条（口令自己换成 bcrypt 串）：

```sql
INSERT INTO mac_admin (admin_name, admin_pwd, admin_status, admin_login_time, admin_login_ip)
VALUES ('admin', '<password_hash>', 1, 0, '');
```

密码列宽 ≥60 用 `password_hash()`（bcrypt，`mac_hash_password_for_column` 的口径）；列宽 <60 会自动降级 md5，见 `09-安全与权限手册.md §2`。更稳的做法：把 `admin_pwd` 留空先在后台「管理员」页新建，或临时用一次完整向导重装（先备份数据）。

## 5. 在线升级（后台「系统 → 在线升级」）

三步式浏览器推进，代码 [app/admin/controller/Update.php](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Update.php)。

| 步 | 动作 | 细节 |
|---|---|---|
| `step1` | 下载 → 校验 → 解压 | 目标 `https://update.maccms.la/v10/{file}.zip?t=时间戳`；`file` 只允许 `^[a-zA-Z0-9._-]+$`；本地存名 `config('version.code').zip` 放 `app/data/update/`；随后取 `{file}.zip.sha1`，要求 `strpos($remote_sha1, sha1_file(本地包)) === 0`（前缀匹配）；不过就删包报错。校验通过用 **自带的 `PclZip`** 解到**项目根**（`PCLZIP_OPT_PATH, ''` + `PCLZIP_OPT_REPLACE_NEWER`，即只覆盖更新的文件），解完删包，自动跳 step2 |
| `step2` | 跑增量 SQL | `app/data/update/database.php` 存在则 `@include` 取其中的 `$sql`，`mac_parse_sql($sql,0,['mac_'=>$prefix])` 拆条逐句执行，逐条打印成功/失败（**失败不中断**），最后 `unlink` 该文件；不存在就提示「无需更新数据库」 |
| `step3` | 清缓存 | 调后台基类 `_cache_clear()`（清 `runtime/cache`+`runtime/temp`、换 `cache_flag`、重建 `static/js/playerconfig.js`，[app/admin/controller/Base.php:130-182](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L130)）。若 `app/data/update/database.php` 还在，红字提示手工删除 |

### 5.1 三个必须知道的前提

1. **升级源指向官方 v10 目录**（`Update.php:15` 的 base64 串解开是 `https://update.maccms.la/`，再拼 `v10/`）。
   本项目是 ThinkPHP 8 / PHP 8 的 v12 分支，**官方 v10 包不能直接覆盖过来**——那会把 TP5 代码盖回 TP8 树，站点立刻不可用。
   → 在拿到本分支自己的升级包之前，**不要用后台在线升级**。要更新就用 §6 的手工升级。
2. **哈希闸门**：后台基类对除 `Update` 外的所有控制器，都会拿 `config('version.update_hash')` 去比 `md5_file('app/admin/controller/Update.php')`，不一致直接 `exit('核心文件错误')`（[Base.php:27-32](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L27)）。
   你（或任何补丁）改了 `Update.php` 而没同步重算哈希，**整个后台会白页只留一句「核心文件错误」**。恢复办法：
   ```bash
   D:/BtSoft/Btsoft/php/83/php.exe -r "echo md5_file('app/admin/controller/Update.php');"
   # 把输出写进 app/extra/version.php 的 update_hash
   ```
   反过来说：这是防止在线升级把 `Update.php` 换成别人版本的机制，**别为了省事把 `update_hash` 清空**。
3. **`app/extra/version.php` 在版本库里是跟踪的**（`git ls-files` 实测），所以它是会被 Git 覆盖的一类文件——手工升级时若你改了 `code`，注意合并。

## 6. 手工升级（本项目实际采用的方式）

### 6.1 先备份这些「不在版本库里」的文件

`git status` 看不到它们，**一旦被 `rm -rf`/覆盖就没了**：

```
config/database.php        数据库连接与口令
app/extra/maccms.php       站点全部实配，含 api_jwt_secret / interface.pass 等凭据
app/extra/translate.php    翻译服务 appid + secret
app/extra/timming.php      计划任务的实配（runtime 时间戳由程序回写）
runtime/                   会话、缓存、编译模板、日志、备份
upload/                    采集与上传的附件图片
index.html / map.html / wap_index.html   后台「生成静态」的输出物
```

（`.gitignore` 第 17-34 行逐条注明了不入库的原因与代价。升级/换机前**先整份拷到 docroot 之外**。）

### 6.2 覆盖代码

```bash
git fetch && git stash list          # 先看清现场，别在脏工作区动手
git -c core.checkstat=minimal status --porcelain
git merge --ff-only origin/master    # 或按发布包解压覆盖
```

覆盖后必做：

```bash
D:/BtSoft/Btsoft/php/83/php.exe think front:bundle            # 重建五张资源包
D:/BtSoft/Btsoft/php/83/php.exe think front:bundle --check    # 校验包与源文件一致
```
（约定见 `07-定时任务与运维手册.md §9`；不重建会出现「CSS/JS 404 或样式错乱」。）

### 6.3 数据库增量

本项目没有自动迁移器。升级包若带 `app/data/update/database.php`，两条路：

- 临时可用在线升级的 step2/step3（**只跑这两步**，跳过 step1 下载）：访问 `admin.php/update/step2`、`admin.php/update/step3`。
- 或把 `$sql` 内容手工在 MySQL 里执行，注意把 `mac_` 换成你的实际前缀（程序靠 `mac_parse_sql(..., ['mac_'=>$pre])` 做这层替换，`Update.php:118`）。

跑完**确认 `app/data/update/database.php` 已删除**——它是「一次性脚本」，留着会在下次 step2 再跑一遍，而且它不属于源码树（口径见项目说明「Schema 注释与升级脚本规则」）。

### 6.4 收尾

1. 后台「清缓存」（`base/_cache_clear`）；或 `rm -rf runtime/cache/* runtime/temp/*`。

## 7. 数据库备份与还原

后台「数据库」模块（[app/admin/controller/Database.php](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Database.php)，实际备份引擎是 `app/common/util/Database.php`）：

| 动作 | 说明 |
|---|---|
| `export`（POST） | 按表逐张导出到 `db.backup_path`（出厂 `./app/data/backup/database/`）。同一次导出会**把含 `_admin` 的表排到最后**（`Database.php:79-86`）。分卷大小 `db.part_size`（出厂 20971520 = 20 MB），`db.compress=1` + `db.compress_level=4` 表示 gzip 分卷。执行前创建 `backup.lock`，正常/异常都会删掉——**残留 lock 会挡住下一次备份**（报「有备份任务」），确认没有备份进程后手工删该文件即可 |
| `import` | 从备份目录里选一分卷集还原；同样是浏览器多跳推进 |
| `optimize` / `repair` | 对选中表做 `OPTIMIZE` / `REPAIR` |
| `del` | 删备份文件 |
| `sql` | 后台直接执行 SQL（超级用户功能，权限面见 `09-安全与权限手册.md §4`） |
| `uploadStorage` | 备份完成后转存到已配置的对象存储（七牛/又拍/阿里在 `extend/` 下） |

**升级前的稳妥组合**：后台「数据库 → 备份全库」跑一次 + 命令行再兜一层：

```bash
D:/BtSoft/Btsoft/mysql/MySQL5.7/bin/mysql.exe -uroot -p -D maccms12 \
  -e "select count(*) from mac_vod"        # 记录基线行数，便于升级后比对
```

> 表引擎口径：内容表（`mac_vod`/`mac_art`/…）是 **MyISAM**，`ROLLBACK` 对它们无效。任何「先改再回滚」的试探手法在内容表上都会真的生效——这条教训来自本项目的实测，见 `90-变更记录.md`。

## 8. 迁移到新服务器

1. 停写：临时把 `site.site_status` 设 `0`（前台出 `public/close.html`），或 crontab 先注释掉。
2. 备份：数据库（§7）+ 拷 `upload/`、`app/data/backup/`、`app/extra/*.php`、`config/database.php`。
3. 部署代码（Git 克隆或整包上传），`chmod`/属主让 §2.3 那 7 处可写。
4. 新库导入备份，改 `config/database.php` 的连接参数。
5. **不必重跑安装向导**——`app/extra/maccms.php` 一起搬过去即可。若选择重装（想清库），注意 §5.1 的哈希闸门与 §3.2 的密钥重生成。
6. 改 `site.site_url` / `site_wapurl` / `site.install_dir`（子目录部署时 `install_dir` 必须是 `/子目录/`，否则静态与图片路径全错）。
7. 多域名分发：`app/extra/domain.php` 的条目按新域名重写。
8. 装 Web 服务器规则（含访问控制段）。
9. `php think front:bundle`、后台清缓存、冒烟测试、恢复 `site_status=1` 与 crontab。
10. 若新机 IP 变了：确认 `api.php` 的采集来源白名单、`interface` 对端回调、`publicapi` 的域名授权列表（`06-接口与采集手册.md §2`）。

## 9. 排障速查

| 现象 | 真因与处置 |
|---|---|
| 打开 `install.php` 显示「PHP版本需要 >= 8.0.2」 | 换 PHP 8；别改 `install.php` 里的判断绕过 |
| 显示「请开启[runtime]目录的读写权限」 | `runtime/` 不存在或属主不对；`mkdir -p runtime && chown` |
| 向导第 2 步有红项、第 3 步点了没反应 | 环境检测没过，`session('install_error')` 拦住了。补齐扩展即可（`zip` 见 §2.2） |
| 「数据库连接错误」 | 先看消息里的 host/port/user；`hostport` 只填数字（校验 `number`） |
| 前缀一直报参数错误 | 必须 `^[a-z0-9]{1,20}[_]{1}$`：小写、以 `_` 结尾 |
| 装完打不开后台，`mac_admin` 是空表 | §3.2 的失效判断导致管理员没建成 → §3.3 手工补 |
| 后台整页只有「核心文件错误」 | `Update.php` 被改过而 `version.update_hash` 没重算（§5.1 第 2 条） |
| 在线升级下到一半报「下载失败」/「sha1 校验失败」 | 官方源是本分支不该用的 v10 包（§5.1 第 1 条）；改走手工升级 |
| 升级后前台样式全乱 / JS 404 | 没重建资源包，`php think front:bundle` |
| 升级后某些功能 500 且报「配置项不存在」 | 旧 `maccms.php` 缺新增配置段，后台对应页保存一次（§6.4 第 3 步） |
| 备份报「有备份任务进行中」 | `app/data/backup/database/backup.lock` 残留，确认后删掉 |
| 想重装但没有 `install.lock` 提示 | 提示里就是路径，删 `app/data/install/install.lock`；重装会重跑 `install.sql`，**先备份** |
