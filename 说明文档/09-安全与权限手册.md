# 安全与权限手册

面向站长的运维口径：谁可以访问什么、请求怎么被拦、文件怎么被藏、哪些地方**目前代码里根本没有防护**（务必看 §8）。
所有结论按当前树逐行核对（2026-10-26）；路径相对站点根目录。文中只写配置**键名**，绝不写任何密钥值。

## 2. 后台登录

- 表单 → [app/admin/controller/Index.php:20-32](.../app/admin/controller/Index.php#L20) → [app/common/model/Admin.php:108-156](.../app/common/model/Admin.php#L108)。
- 验证码：受 `app.admin_login_verify` 控制，**默认 `'1'`（开启）**，值为 `'0'` 才跳过 `captcha_check()`（[Admin.php:114-115](.../app/common/model/Admin.php#L114)）。
- 密码：**bcrypt**（`password_hash`，[mac_hash_password](.../app/common.php#L274)）。校验函数
  [mac_verify_password](.../app/common.php#L279) 先认 `$2` 开头的 bcrypt，**否则回退 md5/明文比对**——
  这是为兼容 v10 老数据；登录成功后若 `mac_password_needs_rehash()` 为真会惰性升级哈希（[Admin.php:142-144](.../app/common/model/Admin.php#L142)）。
- 列宽陷阱：写密码前会探列宽，`admin_pwd` 列 < 60 字符时只能存 md5（[mac_pwd_column_fits_hash](.../app/common.php#L318)、[mac_hash_password_for_column](.../app/common.php#L344)）。
  **升级老库请先确认 `admin_pwd` 是 `varchar(60)` 以上**，否则 bcrypt 会被静默降级。
- 会话：`session('admin_auth')==='1'` + `session('admin_info')`（[Admin.php:151-153](.../app/common/model/Admin.php#L151)）。
  另有 Cookie 自动登录 `checkLogin2()`，判据是 `md5(admin_random-name-id-client_ip)`（[Admin.php:178-204](.../app/common/model/Admin.php#L178)）
  —— **换 IP 会失效**，且它依赖 `mac_get_client_ip()`；在多层代理后面请把可信代理配到 `trusted_proxies`，否则 IP 判定不可靠。
- 锁屏：后台锁定后需重新验密码，[Index.php:240-250](.../app/admin/controller/Index.php#L240)。

> ⚠️ **后台登录没有防爆破/频率限制**。全仓未找到任何 admin 登录失败计数、锁定或限流代码（前台会员登录有，见 §8）。
> 唯一减速手段是验证码，而它可以被 `app.admin_login_verify='0'` 关掉。请把它当成部署前提来处理：
> 要么保持验证码开启，要么在 `admin.php` 前面加 Web 层限制 / 改入口文件名 / 走 VPN 或 IP 白名单。

## 3. 权限模型（谁能点哪个动作）

两套完全不同的体系，别混：

| | 后台管理员 | 前台会员 |
|---|---|---|
| 权限存储 | `mac_admin.admin_auth`（逗号串，形如 `,vod/data,vod/info,`） | `mac_group.group_popedom` |
| 判定函数 | [Base::check_auth()](.../app/admin/controller/Base.php#L54) | [All::check_user_popedom()](.../app/common/controller/All.php#L1106) |
| 动作目录 | [app/admin/common/auth.php](.../app/admin/common/auth.php)（16 个顶级分组、约 2686 行） | 模板 + 分类 `type_popedom` |

要点：
- **`admin_id == 1` 无条件放行**（[Base.php:119](.../app/admin/controller/Base.php#L119)），其余按 `strpos($auths, ',控制器/动作,')`。
- 每个管理员的权限串保存时补前后逗号（[Admin.php:48-50](.../app/common/model/Admin.php#L48)），所以是**精确子串匹配**，不是前缀匹配。
- `auth.php` 里的 `show=1` **只决定左菜单是否出现**，不决定权限；`show=0` 的动作照样存在、照样要授权才能用（这是最常见的误判）。
- 勾选框的 value 是 `{$sub.controller}/{$sub.action}`（[admin/info.html:43](.../app/admin/view/admin/info.html#L43)），**不含 `param`**。所以左栏那些靠 `param` 区分的子集页（重名 `repeat=1`、无地址 `url=1`、未审核 `status=0`、已驳回 `status=2`、草稿 `status=3`、定时发布 `status=4`、需积分 `points=1`、有分集剧情 `plot=1`）与主列表 **共用同一条 `vod/data`**：勾一次全放开，也无法只授权某个子集。
- 固定放行动作：`index/index`、`index/welcome`、`index/logout`、`index/unlocked` 拼在 `$auths` 尾部（[Base.php:117](.../app/admin/controller/Base.php#L117)）。
- 特例判定（[Base.php:59-115](.../app/admin/controller/Base.php#L59)）：
  - `upload/ueditor_ai*` **恒放行**（因为富文本上传必须对任何编辑角色可用）；
  - `assistant/chat|ping` 受 `admin_assistant.access_scope` 控制，`super` = 仅 `admin_id=1`；
  - `safety/fix`、`database/uploadstorage`、`addon/cloudcatalog`、`*contentlangtranslate`、`system/index` 各有等价权限判定。
- 菜单渲染同样调 `check_auth()` 过滤（[Index.php:57](.../app/admin/controller/Index.php#L57)、[:112](.../app/admin/controller/Index.php#L112)），所以「菜单里没有」≠「动作不可调用」。
- 工具型控制器 `Base` 本身不允许被直接路由访问（`$this->_cl === 'Base'` 抛错，[Base.php:21-23](.../app/admin/controller/Base.php#L21)）。
  `protected` 在 TP8 路由下挡不住外部调用，**必须靠控制器名拦**——这是本项目踩过的坑。

## 4. CSRF：两套令牌并存

| 令牌 | 生命周期 | 存放 | 来源 |
|---|---|---|---|
| `__token__` | **一次性**，校验通过即销毁 | Session | ThinkPHP 框架（`Request::checkToken`，`vendor/topthink/framework/src/think/Request.php:1906`） |
| `admin_csrf` | **稳定**，整会话复用、不消耗 | Session `admin_csrf` | [mac_admin_csrf_token()](.../app/common.php#L3671) |

- 页面输出：`<meta name="mac-admin-csrf">`（[app/admin/view/public/head.html:6](.../app/admin/view/public/head.html#L6)）；AJAX 自动带头 `X-CSRF-Token`（[static/js/admin_common.js:38](.../static/js/admin_common.js#L38) 的 `$.ajaxSetup`）。
- 模板内嵌 `{:mac_admin_csrf_token()}`：head.html + 15 个 `info.html` + `configuseraccess.html`。
- 合并校验在 [app/common/validate/Token.php:17-33](.../app/common/validate/Token.php#L17)：先拿 body 的 `__token__` 或 `X-CSRF-Token` 头与稳定的 `Session['admin_csrf']` 做 `hash_equals`，
  命中即通过且**不消耗**；认不出才退回框架一次性校验。**这就是「被拒后直接重提会失败」的修复**：稳定令牌先认。
- 调用点：**45 处 / 15 个后台控制器文件**（最近核对 2026-10-26），形如 `validate('app\common\validate\Token', [], false, false)`。
  第 4 参 `failException=false` 是关键——否则校验失败会抛异常走 500 调试页而不是回到登录/错误提示。
  另有独立实现：[UserAccessLog::checkAdminCsrf()](.../app/admin/controller/UserAccessLog.php#L18) 与 [System.php:795-796](.../app/admin/controller/System.php#L795)。
- 前台会员侧另有一套 `csrf_token`（session/cookie），只在 `index`/`api` 入口生效（[All.php:391-399](.../app/common/controller/All.php#L391)）。

> ⚠️ 三个配置键 `app.security_csrf_admin`（默认 `'0'`）、`security_csrf_admin_exempt`（默认 `upload/*`）、`security_csrf_http_code`（默认 `'403'`）
> 位于 [maccms.php:113-115](.../app/extra/maccms.php#L113)，
> 但**它们不参与运行期强制**——只被安全体检读（[System.php:248](.../app/admin/controller/System.php#L248)、`SecurityHealthCheck.php`）和表单展示。
> 后台 CSRF 的实际强度取决于各 action 是否调用 Token 校验器，**不是这个总开关**。别把它当护身符。

## 5. 核心文件哈希闸门

[app/admin/controller/Base.php:25-31](.../app/admin/controller/Base.php#L25)：除 `Update` 控制器外，
每个后台请求比较 `md5_file(app/admin/controller/Update.php)` 与 `config('version.update_hash')`（存在 [app/extra/version.php:11](.../app/extra/version.php#L11)）。
不匹配 → `exit(lang('admin/update/core_file_error'))`：**整站后台一行白字，无 500、无日志**。

- 保护对象是升级入口 `Update.php` 本身（防被替换后门）。
- **改了 `Update.php`（哪怕只动空格或注释）就必须重算哈希**，否则后台挂死，只能手工重基线。
- 该文件头部声明由官方升级流程维护，站长不应手改。

## 6. 文件与网络操作

### 6.1 上传

- 入口：[app/admin/controller/Upload.php:36-39](.../app/admin/controller/Upload.php#L36) → [app/common/model/Upload.php](.../app/common/model/Upload.php)。
- **扩展名白名单硬编码**在 [Upload.php:56-58](.../app/common/model/Upload.php#L56)，**没有配置项**：
  图片 `jpg jpeg png gif webp`；文件 `doc docx xls xlsx ppt pptx pdf wps txt rar zip torrent`；媒体 `rm rmvb avi mkv mp4 mp3`。
- MIME 为 `text/x-php` 直接拒（[Upload.php:146-148](.../app/common/model/Upload.php#L146)）；base64 路径同样按图片白名单。
- **没有「最大字节」配置键**：`maccms.upload` 段（[maccms.php:209-275](.../app/extra/maccms.php#L209)）只有水印/缩略图/远端存储参数。
  唯一显式上限出现在后台批量导入：`Base.php:233` 传 20 MB、白名单 `csv,txt,xlsx`。**普通附件上传的尺寸只受 PHP `upload_max_filesize`/`post_max_size` 约束。**
- `upload/` 目录**故意保持可 HTTP 访问**（根 `.htaccess:10-12` 的注释说明了理由）；它的 PHP 执行拦截依赖上面的扩展名白名单，
  **没有目录级 `.htaccess` 或 `.user.ini` 来禁 PHP 执行**——这是现状，不是漏查。若你担心，请在 Web 层给 `upload/` 加 `php_flag engine off` / `Location` 禁解析。

## 7. 内部文件不外泄：一份名单，五处派生

拦截名单只有**一个**可信来源——[app/common/util/BlocklistRules.php](.../app/common/util/BlocklistRules.php) 里的五个常量：`DIRS`、`EXTENSIONS`、`BACKUP_SUFFIXES`、`ROOT_FILES`、`DOT_EXEMPT`（[:6-10](.../app/common/util/BlocklistRules.php#L6)）。
其余五份文件（根 `.htaccess`、示例 `.htaccess`、`maccms.conf`、`web.config`、`router.php`）中的拦截段全是它的**渲染产物**：
`targets()`（[:14-23](.../app/common/util/BlocklistRules.php#L14)）声明每份文件要刷新哪几个区块，`check()`（[:60-118](.../app/common/util/BlocklistRules.php#L60)）按 `FENCE = 'maccms:blocklist'`（[:12](.../app/common/util/BlocklistRules.php#L12)）成对定位围栏并整段替换。
命令入口与退出码见 `07-定时任务与运维手册.md §9`（`php think blocklist:sync [--check]`）；**改名单只改一处**：编辑常量 → `sync` 写回 → `--check` 复验，当前基线 5 份全 `ok`。
围栏本身是注释（Apache/nginx 用 `#`、IIS 用 `<!-- -->`、`router.php` 用 `//`），围栏**外**的手写规则一概不被覆盖；标记只剩一边报 `broken-fence`、整对不见报 `no-fence`，不会静默跳过（[app/command/BlocklistSync.php:24-45](.../app/command/BlocklistSync.php#L24)）。`php think doctor` 有一节直接调 `BlocklistRules::check()`（[app/command/Doctor.php:392-401](.../app/command/Doctor.php#L392)）。

| 内置服务器 `php -S` | [router.php](.../router.php) 围栏 [:3-9](.../router.php#L3) | 围栏只渲染五个变量（`$internalDirs` [:4](.../router.php#L4) … `$deniedDotExempt` [:8](.../router.php#L8)），判断逻辑在围栏外：先用 `realpath()` 把 URL 解到真实路径、`%2e%2e` 与软链接都按解析后的结果算（[:17-30](.../router.php#L17)），再拦**任意深度**的点开头条目（[:38-44](.../router.php#L38)）、备份后缀、末段危险后缀、根级点名（含 `router.php` 自身），命中统一回 403（[:46-57](.../router.php#L46)） |
| 目录自带 `.htaccess` | [说明文档/.htaccess](.../说明文档/.htaccess#L7)、[app/.htaccess](.../app/.htaccess#L1) | 整目录 `Require all denied` / `deny from all`，随目录一起复制即生效，不依赖站点全局配置——所以单发一份 `说明文档/` 给别人也不会漏正文 |

- **`.htaccess` 之外还有框架层**：[config/app.php:18](.../config/app.php#L18) 的 `deny_module_list`（`common / data / extra / lang`）禁止 ThinkPHP 把这四个目录当模块解析，是同一思路的最后一环（参数口径见 `02-站点配置参考.md`）；减了它，`app/extra/` 下的敏感配置在多应用路由写法下就有暴露面。
- **`ROOT_FILES` 为什么逐个点名**：`.lock` 已被 `EXTENSIONS` 挡住，`composer.json` 与 `think` 没有危险后缀，`router.php` 只在 `php -S` 下是入口；`.json` 不能整类拦——后台 Swagger 还要读 `static/swagger/*.json`。
- **备份后缀为什么要两条规则**：Apache `FilesMatch` 与 nginx 正则能写 `([._]…)?$`，但 IIS 的 `requestFiltering.fileExtensions` 只认**最后一段**后缀，`x.bak_20261024` 会漏，所以 IIS 另用一条 URL 规则兜住。
- **围栏外的手写内容不会被覆盖**，但根 `.htaccess` 除访问控制外还负责**文本压缩与静态资源过期**两段（[:61-102](.../.htaccess#L61)，口径见 `01-安装与升级手册.md §4.1`）。这两段不在名单范围内，`说明文档/伪静态规则/` 的示例文件**没有同步**，`router.php` 也不做压缩。
- **只有三个目录有自带 `.htaccess`**（根、`app/`、`说明文档/`）；`config/`、`runtime/`、`vendor/`、`extend/`、`upload/` 都没有，全靠根规则与 `router.php`。换 Web 服务器时请手工补齐等价规则。
- 伪静态规则文件本身在 `说明文档/` 里，而该目录被整目录拒绝——**要拷规则到 nginx 时得从文件系统取，不能从 HTTP 下载**；后台「文档与手册」读的是文件内容，不是 HTTP。
- ⚠️ 名单变严是**单向**的：`blocklist:sync` 会把五份文件同时收紧，改完常量跑一次就够了，但别只改一份「测试一下」——`--check` 会立刻报 `drift`，`doctor` 也会。
- **本批次收敛时相比旧的手写五份副本，新拦下的**：Apache 两套（根与示例）此前都不点名 `router.php`；nginx 此前不拦 `.user.ini` 与 `router.php`；IIS 此前**既不拦隐藏文件/目录**（`hiddenSegments` 匹配不到以点开头的名字）**也不拦任何根级清单文件**；`router.php` 此前只看**首段**，把隐藏目录夹在路径中间（`/static/.git/config`）能放行。反向没有放松任何一条。
