## 2. 后台登录

- 表单 → [app/admin/controller/Index.php:20-32](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Index.php#L20) → [app/common/model/Admin.php:108-156](file:///D:/wwwroot/maccms/maccms12/app/common/model/Admin.php#L108)。

- 密码：**bcrypt**（`password_hash`，[mac_hash_password](file:///D:/wwwroot/maccms/maccms12/app/common.php#L311)）。校验函数
  [mac_verify_password](file:///D:/wwwroot/maccms/maccms12/app/common.php#L316) 先认 `$2` 开头的 bcrypt，**否则回退 md5/明文比对**——
  这是为兼容 v10 老数据；登录成功后若 `mac_password_needs_rehash()` 为真会惰性升级哈希（[Admin.php:142-144](file:///D:/wwwroot/maccms/maccms12/app/common/model/Admin.php#L142)）。
- 列宽陷阱：写密码前会探列宽，`admin_pwd` 列 < 60 字符时只能存 md5（[mac_pwd_column_fits_hash](file:///D:/wwwroot/maccms/maccms12/app/common.php#L355)、[mac_hash_password_for_column](file:///D:/wwwroot/maccms/maccms12/app/common.php#L381)）。
  **升级老库请先确认 `admin_pwd` 是 `varchar(60)` 以上**，否则 bcrypt 会被静默降级。
- 会话：`session('admin_auth')==='1'` + `session('admin_info')`（[Admin.php:151-153](file:///D:/wwwroot/maccms/maccms12/app/common/model/Admin.php#L151)）。
  另有 Cookie 自动登录 `checkLogin2()`，判据是 `md5(admin_random-name-id-client_ip)`（[Admin.php:178-204](file:///D:/wwwroot/maccms/maccms12/app/common/model/Admin.php#L178)）
  —— **换 IP 会失效**，且它依赖 `mac_get_client_ip()`；在多层代理后面请把可信代理配到 `trusted_proxies`，否则 IP 判定不可靠。
- 锁屏：后台锁定后需重新验密码，[Index.php:240-250](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Index.php#L240)。

> ⚠️ **后台登录没有防爆破/频率限制**。全仓未找到任何 admin 登录失败计数、锁定或限流代码（前台会员登录有，见 §8）。
> 唯一减速手段是验证码，而它可以被 `app.admin_login_verify='0'` 关掉。请把它当成部署前提来处理：
> 要么保持验证码开启，要么在 `admin.php` 前面加 Web 层限制 / 改入口文件名 / 走 VPN 或 IP 白名单。

## 3. 权限模型（谁能点哪个动作）

两套完全不同的体系，别混：

| | 后台管理员 | 前台会员 |
|---|---|---|
| 权限存储 | `mac_admin.admin_auth`（逗号串，形如 `,vod/data,vod/info,`） | `mac_group.group_popedom` |
| 判定函数 | [Base::check_auth()](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L54) | [All::check_user_popedom()](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L1106) |
| 动作目录 | [app/admin/common/auth.php](file:///D:/wwwroot/maccms/maccms12/app/admin/common/auth.php)（16 个顶级分组、约 2686 行） | 模板 + 分类 `type_popedom` |

要点：
- **`admin_id == 1` 无条件放行**（[Base.php:119](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L119)），其余按 `strpos($auths, ',控制器/动作,')`。
- 每个管理员的权限串保存时补前后逗号（[Admin.php:48-50](file:///D:/wwwroot/maccms/maccms12/app/common/model/Admin.php#L48)），所以是**精确子串匹配**，不是前缀匹配。
- `auth.php` 里的 `show=1` **只决定左菜单是否出现**，不决定权限；`show=0` 的动作照样存在、照样要授权才能用（这是最常见的误判）。
- 勾选框的 value 是 `{$sub.controller}/{$sub.action}`（[admin/info.html:43](file:///D:/wwwroot/maccms/maccms12/app/admin/view/admin/info.html#L43)），**不含 `param`**。所以左栏那些靠 `param` 区分的子集页（重名 `repeat=1`、无地址 `url=1`、未审核 `status=0`、已驳回 `status=2`、草稿 `status=3`、定时发布 `status=4`、需积分 `points=1`、有分集剧情 `plot=1`）与主列表 **共用同一条 `vod/data`**：勾一次全放开，也无法只授权某个子集。
- 固定放行动作：`index/index`、`index/welcome`、`index/logout`、`index/unlocked` 拼在 `$auths` 尾部（[Base.php:117](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L117)）。
- 特例判定（[Base.php:59-115](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L59)）：
  - `upload/ueditor_ai*` **恒放行**（因为富文本上传必须对任何编辑角色可用）；
  - `assistant/chat|ping` 受 `admin_assistant.access_scope` 控制，`super` = 仅 `admin_id=1`；
  - `safety/fix`、`database/uploadstorage`、`addon/cloudcatalog`、`*contentlangtranslate`、`system/index` 各有等价权限判定。
- 菜单渲染同样调 `check_auth()` 过滤（[Index.php:57](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Index.php#L57)、[:112](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Index.php#L112)），所以「菜单里没有」≠「动作不可调用」。
- 工具型控制器 `Base` 本身不允许被直接路由访问（`$this->_cl === 'Base'` 抛错，[Base.php:21-23](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L21)）。
  `protected` 在 TP8 路由下挡不住外部调用，**必须靠控制器名拦**——这是本项目踩过的坑。

## 4. CSRF：两套令牌并存

| 令牌 | 生命周期 | 存放 | 来源 |
|---|---|---|---|
| `__token__` | **一次性**，校验通过即销毁 | Session | ThinkPHP 框架（`Request::checkToken`，`vendor/topthink/framework/src/think/Request.php:1906`） |
| `admin_csrf` | **稳定**，整会话复用、不消耗 | Session `admin_csrf` | [mac_admin_csrf_token()](file:///D:/wwwroot/maccms/maccms12/app/common.php#L3930) |

- 页面输出：`<meta name="mac-admin-csrf">`（[app/admin/view/public/head.html:6](file:///D:/wwwroot/maccms/maccms12/app/admin/view/public/head.html#L6)）；AJAX 自动带头 `X-CSRF-Token`（[static/js/admin_common.js:38](file:///D:/wwwroot/maccms/maccms12/static/js/admin_common.js#L38) 的 `$.ajaxSetup`）。
- 模板内嵌 `{:mac_admin_csrf_token()}`：head.html + 15 个 `info.html` + `configuseraccess.html`。
- 合并校验在 [app/common/validate/Token.php:17-33](file:///D:/wwwroot/maccms/maccms12/app/common/validate/Token.php#L17)：先拿 body 的 `__token__` 或 `X-CSRF-Token` 头与稳定的 `Session['admin_csrf']` 做 `hash_equals`，
  命中即通过且**不消耗**；认不出才退回框架一次性校验。**这就是「被拒后直接重提会失败」的修复**：稳定令牌先认。
- 调用点：**45 处 / 15 个后台控制器文件**（最近核对 2026-10-26），形如 `validate('app\common\validate\Token', [], false, false)`。
  第 4 参 `failException=false` 是关键——否则校验失败会抛异常走 500 调试页而不是回到登录/错误提示。
  另有独立实现：[UserAccessLog::checkAdminCsrf()](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/UserAccessLog.php#L18) 与 [System.php:795-796](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/System.php#L795)。
- 前台会员侧另有一套 `csrf_token`（session/cookie），只在 `index`/`api` 入口生效（[All.php:391-399](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L391)）。

> ⚠️ 三个配置键 `app.security_csrf_admin`（默认 `'0'`）、`security_csrf_admin_exempt`（默认 `upload/*`）、`security_csrf_http_code`（默认 `'403'`）
> 位于 [maccms.php:113-115](file:///D:/wwwroot/maccms/maccms12/app/extra/maccms.php#L113)，
> 但**它们不参与运行期强制**——只被安全体检读（[System.php:248](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/System.php#L248)、`SecurityHealthCheck.php`）和表单展示。
> 后台 CSRF 的实际强度取决于各 action 是否调用 Token 校验器，**不是这个总开关**。别把它当护身符。
