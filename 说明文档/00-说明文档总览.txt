================================================================================
maccms12 说明文档总览
================================================================================
maccms12 = 苹果 CMS v10（maccms10）整树升级版，核心框架实装 ThinkPHP 8.1.4
（多应用模式），由 maccms10-2026.1000.4056（TP5.1）迁移重写。本目录按官方
maccms10「说明文档」结构建立，内容以 maccms12 实际实现为准（API 方法、
数据库表、标签库均已实测核对）。

二、maccms12 版本与环境
--------------------------------------------------------------------------------
· 运行环境：PHP >= 8.0.2（composer.json 的 require.php；本机验证用 PHP 8.3.8）、
  MySQL 5.7/8.0+（本机 5.7.38）、Nginx/Apache/PHP 内置服务器均可。
· 入口文件：index.php（前台）、admin.php（后台）、api.php（接口/定时任务）、
  install.php（安装，已装后访问提示已锁；锁文件为 app/data/install/install.lock）。
· 数据库：maccms12（84 张表，前缀 mac_，含 mac_content_lang 内容语言表）；
  唯一配置来源 config/database.php（安装程序写入后会热更新进框架 Config，
  不存在第二份镜像）。
· 默认后台账号：admin（口令不写入文档，正式环境务必改密）；验证码开关
  app/extra/maccms.php → admin_login_verify（1 开 / 0 关）。
· 完整交付说明见项目根目录 README.md。

三、与 maccms10 核心差异（TP8 升级，功能/数据结构保持兼容）
--------------------------------------------------------------------------------
1. 目录结构：application/ → app/（模块 admin/api/index/install 按 TP8 多应用布局）。
2. 入口引导：四个入口重写为 TP8 引导并修复 PATHINFO 解析。
3. TP5 行为（application/tags.php 里的 behavior/*）迁为 TP8 全局中间件，
   声明在 app/middleware.php，实现放在 app/common/middleware/。除框架自带的
   SessionInit 外共 12 个，按执行顺序：SessionSameSite / Init / AddonInit /
   RequestSecurity / Begin / IpBlock / AntiScrape / MonitorRequest /
   PreviewLinks / SecurityHeaders / CookieSameSite / AdminAudit；
   application/tags.php 已删除。
4. 公共层 app/common.php 提供 mac_* 助手函数族（200+ 个顶层函数），承担原 TP5
   公共层职责：配置读写 mac_load_extra() / mac_arr2file() / mac_save_config_data()，
   模板与 URL mac_tpl_file() / mac_url()，输出 mac_echo() / mac_jump() 等。
   （注：本文旧版在这里列的 mac_config_set()、model()、THINK_VERSION 三个「兼容层」
   在当前代码里并不存在，属笔误，已按实际函数改写。）
5. 数据库配置单一来源：config/database.php（TP8 connections 结构）。安装程序
   写完文件后会 include 进框架 Config 热更新，不再保留 TP5 时代的第二份镜像。
6. vendor 保持 Composer 原样：三处 TP5 写法已改为 TP8 原生调用，不再有 vendor 补丁，
   因此 composer update 之后无需任何重打补丁步骤（清理记录见项目根 README.md）。
7. 清理项：删除 behavior 惰性代码、theme-request-form/、tests/、storage/、
   app/tags.php；static_new/ 已并入 static/（全库 0 处 static_new 引用）。
   根 route/ 目录并未删除，只剩 route/addons.php（插件统一路由
   addons/:addon/:controller/:action → app\common\addon\Dispatcher@run），
   由 app/index/route/addons.php require 复用；前台 rewrite 规则在
   app/index/route/rewrite.php，两者不要混为一谈。
8. 后台视图与控制器里的 application/ 路径已全部改为 app/（迁移时一次性改过 352 处；
   本次复查 app/admin/view/ 下已 0 处残留，剩下的 application/json 等是 MIME 类型）。
   模板（template/）与前台标签语法完全兼容 maccms10，可无损复用。

7. 【2026-10-25 后台左侧菜单按功能重排（23 组 / 360 个节点）】
   原则是「不合并」：只把大杂烩组拆开，内容模块组原样保留。现在的 23 组依次为
   首页 / 视频 / 漫画 / 文章 / 网址 / 直播 / 基础资料 / AI 能力 / 互动 / 会员账户 /
   营销与交易 / 运营统计 / 主题与模板 / 静态生成 / 采集中心 / 站点设置 /
   通知与推送 / 扩展与权限 / 数据库与备份 / 安全与风控 / 监控与告警 / 日志与审计 /
   文档与手册。原先的「系统设置」「运维与安全」「会员与营销」「界面与生成」「内容基础」
   「数据采集」等组名不再存在，本文档里凡引用后台菜单位置的地方都按新组名书写。
   - 组名文案取自 app/lang/*.php 的 menu/* 键（6 份语言包全部补齐，auth.php 引用的
     362 个键在 6 份包里 0 缺失）。
   - 权限不受影响：mac_admin.admin_auth 存的是 controller/action 字符串，不是菜单键，
     重排分组不会让既有子管理员授权失效。
   - 顺带修掉四处历史 bug：① 首页快捷菜单节点用 13 / 14+k 的魔法键，会与真实菜单节点
     撞号，改为 900000+；② 管理员权限页把「欢迎页面」固定勾选的判断写死菜单键数字，
     改为按 controller/action=index/welcome 判定；③ 左侧菜单模板输出 <i class="{$vv['icon']}">
     读取的是节点里根本不存在的键，每次渲染 131 个空 <i>，已删；④ 节点 821「生成WAP首页」
     的 param 拼接方式失效，改为显式 'param' => 'ac2=wap'。
   - 已实测：23 个顶级组在 PC 顶栏（横向滚动不换行）与移动端抽屉都正常切换，131 个菜单项
     data-id 唯一；123 个只读页面逐个访问均 200、无 PHP 报错、无「权限」拒绝文案；
     「欢迎页面」常驻标签（1-11）复用不重复；管理员权限树列出 23 组新组名、
     welcome 仍为选中且只读。
