========================================================================
maccms12（ThinkPHP 8）说明
========================================================================
本目录规则文件基于官方 maccms10「伪静态规则」整理，规则本身在 maccms12
（TP8 多应用）下同样适用：前台 index.php、后台 admin.php、接口 api.php、
安装 install.php 均为独立入口文件；除前台外的入口是真实文件，重写规则
只在「请求的不是真实文件/目录」时生效，互不冲突。
· 后台设置：系统 → 网站参数 →「URL地址配置」分页 →「路由伪静态设置」，
  把「伪静态状态」（rewrite.status）打开；用自定义 URL 表达式时同时打开「路由状态」
  （rewrite.route_status）。「浏览模式设置」分页保持各页为「动态」（view.*=0）——
  伪静态与生成静态是两套机制，选了静态就不走 rewrite。
  （官方原文写作「系统 → 网站参数 → 浏览模式 → 选 rewrite伪静态」，maccms12 的
  实际菜单位置就是上面这个，且界面上没有名为「rewrite伪静态」的选项。）
  出厂默认 rewrite.status / route_status 均为 0，即未启用伪静态。
· 入口文件如需改名（如 api.php → api2.php），请同步修改本目录规则。
· 若静态文件后缀配置的不是 html（如 .shtml），请把规则中 .html 替换为
  对应后缀；静态路径前缀在 系统 → 网站参数 →「URL地址配置」→
  「静态路径设置」分页调整。
· maccms12 在 TP8 下同时支持 ?s= 兼容模式：index.php?s=/vod/detail/id/1
  与 PATHINFO 模式：index.php/vod/detail/id/1，规则文件两种均已覆盖。
========================================================================

1，确认空间支持rewrite组件。
2，把本目录（说明文档/伪静态规则/）里对应服务器的规则文件复制到网站根目录。
   （官方原文写的是「伪静态rewrite 目录」，本项目目录名为「伪静态规则」，同一个东西。）
3，后台设置浏览模式为 rewrite伪静态 。


如果使用rewrite伪静态模式，请注意把配置文件复制到网站根目录。
如果静态文件后缀配置的不是html，则请把rewrite配置文件中的.html替换为对应的后缀（如.shtml）。
（官方原文这里写成「替换为对应的后缀如.html」，例子和要替换的目标一模一样，是笔误。）

iis6.x   下使用 httpd.ini

iis7.x   下使用web.config

apache下使用 .htaccess
(根目录安装：直接复制即可，示例文件未写 RewriteBase。
 装在子目录时：在 RewriteEngine on 之后补一行 `RewriteBase /子目录`，
 例如站点在 /maccms12 下就写 `RewriteBase /maccms12`。)

nginx 下使用 maccms.conf
(使用vps或者服务器的可以在你的主机的conf里 用 include xxxxx.conf   也就是包含下伪静态规则文件
如果用的是虚拟主机版的nginx 就找你的主机商给你添加规则就行，你把规则发给他。)

附：内部文件访问控制（与伪静态规则配套）
========================================================================
本项目的网站根目录同时就是程序根目录，因此 说明文档/、runtime/、vendor/、
config/、app/、extend/、composer.json、composer.lock、think、.user.ini 以及
*.md / *.sql / *.log / *.lock / *.wpm / *.sh / *.ps1 / *.py 和 *.bak / *.old /
*.orig（含 .bak_20261024 这类带日期的后缀）默认可以被浏览器直接下载。
上述规则文件里已内置拦截段落，按服务器对应关系操作：

  apache     根目录 .htaccess 已随包提供（另有 说明文档/.htaccess 随目录生效，
             内容为整目录 Require all denied）。
             如把本目录示例 .htaccess 复制为根目录文件来启用伪静态，请连同
             其中的访问控制段落一起保留——示例文件与根目录 .htaccess 的拦截
             名单一致（含 .bak/.old/.orig 段）。
  nginx      用本目录 maccms.conf 的 location 拦截块。其中
             「location ^~ /.well-known/」必须排在正则规则之前，
             否则 HTTPS 证书的 HTTP-01 校验会被一起挡掉。
  iis7 及以上 用本目录 web.config 的 requestFiltering（hiddenSegments +
             fileExtensions），IIS 内置功能，无需额外模块。
             备份后缀 .bak_20261024 这种多段后缀 requestFiltering 认不出来，
             所以 web.config 里另有一条 DenyBackupFiles 重写规则兜住。
  iis6       ISAPI_Rewrite 2.x 无可靠的 [F] 拦截、IIS6 没有 requestFiltering，
             httpd.ini 无法提供同等保护，请把 说明文档/ 移出网站根目录
             （站点运行不依赖它；移出后后台「说明文档」阅读页也没有可列的文件，
             手册请在本机另存一份）。
  本地 php -S 根目录 router.php 复刻同样的规则，启动时把 router.php 作为脚本参数：
             php -S 127.0.0.1:8080 -t <网站根目录> router.php

拦截只作用于 HTTP 直接请求：PHP 侧 require/include 读文件不走 HTTP，
程序运行不受影响。前台业务路由与 static/、template/、upload/、addons/、
robots.txt、crossdomain.xml、LICENSE 均保持可访问。
五套规则（根 .htaccess / maccms.conf / web.config / httpd.ini / router.php）
的拦截名单需同步维护，新增根级内部文件时按上面的清单补全。
需要在本目录里查文档正文时，不必放开下载规则：登录后台 →「系统」→
「说明文档」即可在线阅读（后台阅读页只读，读取范围限本目录的 txt/md/conf/ini/
config 与根 README.md，见《00-说明文档总览.txt》第四节说明 6）。
