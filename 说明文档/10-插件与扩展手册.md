# 插件与扩展手册

这本手册回答一个问题：**想给站点加一块新功能，代码该放哪儿、后台点哪儿、程序实际动了哪些文件**。
所有结论按当前代码树逐行核对（2026-10-26）；路径相对站点根目录。文中只写配置**键名**，绝不写任何密钥值。

> [09-安全与权限手册.md](file:///D:/wwwroot/maccms/maccms12/说明文档/09-安全与权限手册.md)（CSRF 两套令牌、内部文件拦截）。

## 1. 四种扩展形态，先分清再去改

| 形态 | 代码放哪儿 | 怎么被发现 | 后台入口 | 落盘产物 | 适合做什么 |
|---|---|---|---|---|---|
| **插件（addon）** | 根目录 `addons/<name>/` | 目录扫描 + 钩子登记表 [app/extra/addons.php](file:///D:/wwwroot/maccms/maccms12/app/extra/addons.php) | 应用 →「本地应用」 | 纯文件（`info.ini`、`config.values.php`、`addons.php`）；只有带 `install.sql` 时才写库 | 一块完整功能：登录页换背景、AI 生成内容、社交模块 |
| **驱动（extend）** | `app/common/extend/<flag>/Xxx.php` | [mac_extends_list()](file:///D:/wwwroot/maccms/maccms12/app/common.php#L595) 目录扫描，**没有注册表** | 网站参数各子页的下拉框 | 站点配置 `app/extra/maccms.php` 对应分区 | 换一家服务商：OSS/七牛上传、短信、收银台、推送 |
| **注册表类**（播放器 / 播放服务器 / 下载方式） | `app/extra/vodplayer.php`、`vodserver.php`、`voddowner.php` | 后台直接 `config('vodplayer')` 读文件，**无数据库表** | 基础数据 → 播放器管理 / 服务器管理 / 下载器管理 | 注册表文件 +（仅播放器）`static/player/<from>.js` | 加一个解析播放器、加一条资源线路 |
| **采集规则** | 数据库 | 后台 CRUD | 采集 → 规则管理 | 库表 | 接一个新资源站（口径见 [06-接口与采集手册.md](file:///D:/wwwroot/maccms/maccms12/说明文档/06-接口与采集手册.md)） |

**没有第五种**：模板主题不是插件，它在 `template/` 下、由「模板管理」页和 `app/extra/mctheme.php` 管；`app/data/addon/` 目录**只放开发者文档**，不放可执行代码（见 §15）。

## 2. 插件包的实际位置与命名约束

- 安装位置是**站点根**的 `addons/`，常量 [MAC_ADDON_PATH](file:///D:/wwwroot/maccms/maccms12/app/common/middleware/Init.php#L95)（= `ROOT_PATH.'addons/'`）；
  助手函数一律用 `root_path('addons')` 拼路径（[helpers.php:16](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L16)）。
  命名空间 `addons\` 已在 [composer.json:33](file:///D:/wwwroot/maccms/maccms12/composer.json#L33) 里按 PSR-4 映射到该目录，
  所以**新装插件不需要 `composer dump-autoload`**（`optimize-autoloader` 只是预生成 classmap，PSR-4 兜底仍在；除非你自己加了 `--classmap-authoritative`）。
- 目录名 / 插件名必须匹配 `^[a-z][a-z0-9_]{0,31}$`（[AddonSecureInstaller::isValidName](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L37)）。
  扫描时用的是稍宽的 `^[a-z][a-z0-9_]*$`（[helpers.php:9](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L9)、[:43](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L43)）——
  **带中划线、大写字母、纯数字开头的目录会被彻底无视**，后台列表里不出现，也不报错。
- 当前仓库内置三个插件，`state` 全是 `0`（即**装着但没启用**）：`adminloginbg`、`aicontent`、`socialws`。

一个能跑起来的包最少需要这些：

```
addons/mytool/
├── info.ini                 # 必需，缺了 addon_info() 返回空数组
├── Mytool.php               # 必需，主类（本地上传还专门校验这个文件存在）
├── config.php               # 可选，配置页字段 schema
├── config.values.php        # 可选，程序生成的值文件，别手改
├── install.sql              # 可选，安装时执行
├── controller/              # 可选，插件自己的页面/接口
├── view/  model/  service/  lang/  assets/   # 可选，插件自定义
└── static/                  # 可选，随包带的静态资源
```

- 主类名由 [addon_class()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L173) 推断：依次试 `addons\<name>\<Ucfirst(name)>`、全小写、下划线转驼峰，取第一个 `class_exists` 的。
- 主类必须继承 [app\common\addon\Addon](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Addon.php)；插件名从**类的命名空间第二段**反推（[Addon::getName](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Addon.php#L25)），所以放错目录会拿到空名字。

## 3. `info.ini` 与配置页 schema

### 3.1 info.ini

读法只有一句：`@parse_ini_file($file, false, INI_SCANNER_TYPED)`（[helpers.php:20](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L20)）——
**不解析分节**，值里出现 `= [ ] " ; #` 需要加引号。

字段清单（内置三个插件实际用的就是这些）：

| 键 | 谁在用 | 说明 |
|---|---|---|
| `name` | 扫描、路由、类名推断 | 与目录名一致；读的时候会被**强制覆写**成目录名（[helpers.php:24](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L24)） |
| `state` | **唯一的开关** | 缺省按 `0`（[:25](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L25)）；只有 `1` 才注册钩子、才能访问插件页面 |
| `version` | 升级比对、云市场列表 | 字符串 |
| `title` / `intro` / `author` / `website` / `image` / `url` | 只用于后台列表页展示 | 程序不解释 |
| `install` | 不来自文件 | 只要 `info.ini` 读成功就被硬置 `1`（[:26](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L26)），表示「包已就位」 |
| `config` | 装完后回填（[Addon.php:612](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L612)） | 有没有 `config.php`，决定列表页是否显示「设置」 |

> **写回会丢注释**：启停插件时 [addon_save_info()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L142) 用 `key = value` 逐行重生成整个文件（[:163](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L163)），
> 分节、注释、数组/对象值一律丢失。想在 `info.ini` 里写说明文字，点一次「启用」就没有了。

### 3.2 配置页字段 schema

`config.php` 返回**索引数组**，每项字段（校验逻辑见 [validateAddonConfigRows](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L680)）：

| 字段 | 含义 |
|---|---|
| `name` | 字段名，必须 `^[a-zA-Z_][a-zA-Z0-9_]*$`，也是存进 `config.values.php` 的键 |
| `title` | 表单标签；留空时用 `name` |
| `type` | 只允许这 13 个：`string text number datetime array checkbox radio select selects image images file files bool`（[:682](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L682)），写别的直接报「类型错误」 |
| `content` | 选项字典（`radio/select/selects` 用它校验取值合法性） |
| `value` | 默认值；运行时被 `config.values.php` 覆盖（[addon_full_config](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L59)） |
| `rule` | 只识别里面有没有 `required`（[:703](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L703)），其它 TP 校验规则**不生效** |
| `msg` `tip` `ok` `extend` | 展示 / 透传给模板 |

保存时：`checkbox`、`selects` 的多值被 `implode(',')` 成字符串；`array` 收 JSON 文本；`bool` 归一成 `'1'/'0'`；单值上限 65535 字节。
落盘是 [addon_save_full_config()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L118) 的 `var_export`，写 `addons/<name>/config.values.php`（[:131](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L131)）。

插件代码里用 `$this->getConfig('字段名', '默认')` 读（[Addon::getConfig](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Addon.php#L39)）。
**读的是请求内缓存**（`$GLOBALS['__addon_config_cache']`），改完文件要下一个请求才生效。

## 5. 启停 / 安装 / 卸载到底改了什么

### 5.1 启用与停用

[Service::enable()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L69) / [disable()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L90) 的四步，顺序固定：

1. 实例化主类，若插件定义了 `enable()`/`disable()` 且**返回 `false`** → 抛异常、状态不变（`force=true` 可跳过）。
2. 把 `state` 写成 `1` / `0` 并**重写 `info.ini`**（[Service.php:83](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L83)、[:103](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L103)）。
3. `AddonManager::reset()` 清进程内已加载实例与 handler 缓存（[AddonManager.php:84](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L84)）。
4. `Service::refresh()` 重写登记表 + 删缓存。

**不动数据库、不动模板、不动静态资源。**

### 5.2 登记表 `app/extra/addons.php`

[Service::refresh()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L123) 每次执行都**整文件重生成**：

```php
return [
    'autoload' => true,      // 恒为 true（[:142](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L142)）
    'hooks'    => [ 'app_init' => ['aicontent'], ... ],  // 反射推出
    'route'    => [],        // 恒为空（[:144](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L144)）
];
```

- `hooks` 来自反射：把每个**已启用**插件主类的 public 方法名转 snake_case（[:135](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L135)），
  并排除静态方法、`Addon` 基类自带方法、`install/uninstall/enable/disable/upgrade` 五个生命周期方法（[:129-133](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L129)）。
- `route` 字段**是历史遗留**：插件页面路由实际写在 [route/addons.php](file:///D:/wwwroot/maccms/maccms12/route/addons.php)，与这个文件无关（见 §7）。
- 最后删掉两个缓存键 `hooks`、`addons`（[:152](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L152)）。
- 写失败会抛 `write addons config failed`，页面报操作失败但 `info.ini` **已经改了**——出现「列表里状态和钩子不一致」时，手工执行一次 `Service::refresh()` 的场景就是它（排障见 §13）。

### 5.3 安装与卸载

| 步骤 | 安装 [Service::install()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L36) | 卸载 [Service::uninstall()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L49) |

| 2 | 调主类 `install()`，返回 `false` 即失败 | —— |
| 3 | 有 `install.sql` 才执行：按 `;` 切句、替换 `__PREFIX__` 为库前缀（[:110-120](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L110)） | —— |
| 4 | `refresh()` | **递归删除 `addons/<name>/` 整个目录**（[:60](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Service.php#L60)）+ `reset()` + `refresh()` |
| 5 | —— | 删之前先 `backupAddon()` 打 zip 到 `runtime/addons/backup/<name>-时间戳.zip`；**备份失败即中止卸载**，异常时才自动回滚（[Addon.php:421-441](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L421)、[Installer:431](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L431)） |

> **卸载不会删表、也不会删数据。** `install.sql` 建的表、插件写到 `upload/` 的文件全都留着；`aicontent` 这类带表的插件卸载后表仍在库里。
> **备份是卸载的前置条件**：[backupAddon()](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L431) 在缺少 `ZipArchive` 时返回 `false`，
> 控制器随即报 `admin/addon/uninstall_backup_fail` 并**直接结束**（[Addon.php:421-425](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L421)），目录一个文件都不会少。
> 也就是说：本机（PHP 无 zip 扩展）**装也装不上、卸也卸不掉**，`force` 参数救不了它——只能手工删 `addons/<name>/` 再启停任意插件触发一次 `refresh()` 重登记表。
> 备份 zip 落在 `runtime/addons/backup/`；只有卸载中途抛异常且目录确实已被删时才会自动回滚（[:430-441](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L430)）。

## 6. Hook：插槽、命名与三条硬约束

调用方一律写成 `addon_hook('钩子名', $参数)`（[helpers.php:203](file:///D:/wwwroot/maccms/maccms12/app/common/addon/helpers.php#L203)），
内部转 [AddonManager::dispatch()](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L44)。

当前代码里**真实存在**的插槽只有 6 个：

| 钩子名 | 主类方法名 | 触发点 | 参数 |
|---|---|---|---|
| `app_init` | `appInit()` | [app/common/middleware/AddonInit.php:11](file:///D:/wwwroot/maccms/maccms12/app/common/middleware/AddonInit.php#L11)（全局中间件，每请求） | 无 |
| `action_begin` | `actionBegin()` | [app/common/controller/All.php:38](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L38) | `think\Request` |
| `view_filter` | `viewFilter()` | [All.php:67](file:///D:/wwwroot/maccms/maccms12/app/common/controller/All.php#L67)、[addon/Controller.php:39,44](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Controller.php#L39) | 渲染后的 HTML 字符串 |
| `admin_login_init` | `adminLoginInit()` | [app/admin/controller/Index.php:30](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Index.php#L30) | `think\Request` |
| `social_broadcast` | `socialBroadcast()` | 社交模型：[Danmaku.php:145](file:///D:/wwwroot/maccms/maccms12/app/common/model/Danmaku.php#L145)、[Chatroom.php:148](file:///D:/wwwroot/maccms/maccms12/app/common/model/Chatroom.php#L148)、[Follow.php:316](file:///D:/wwwroot/maccms/maccms12/app/common/model/Follow.php#L316)、[Dynamics.php:100](file:///D:/wwwroot/maccms/maccms12/app/common/model/Dynamics.php#L100)、[UserPm.php:139](file:///D:/wwwroot/maccms/maccms12/app/common/model/UserPm.php#L139)、[ShareLog.php:137](file:///D:/wwwroot/maccms/maccms12/app/common/model/ShareLog.php#L137) | 数组 |
| （自定义） | —— | 没人调 = 不触发 | —— |

插件里多写的任何 public 方法都会进登记表 `hooks`，但**没有对应的 `addon_hook()` 调用点就永远不会执行**——登记表不是事件总线。

三条必须记住的语义（都在 [dispatch](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L44) 里）：

1. **返回值一律被丢弃**（[:49](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L49) 直接调方法、不接返回值），最后返回的是**传进来的原始 `$params`**（[:54](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L54)）。
   → 插件想改内容，参数**必须按引用接收**。内置包就是这么写的：`adminLoginInit(\think\Request &$request)`（[addons/adminloginbg/Adminloginbg.php:19](file:///D:/wwwroot/maccms/maccms12/addons/adminloginbg/Adminloginbg.php#L19)）、
   `viewFilter(&$content)`、`actionBegin(&$params)`（[addons/aicontent/Aicontent.php:171,192](file:///D:/wwwroot/maccms/maccms12/addons/aicontent/Aicontent.php#L171)）。
   写成 `viewFilter($content)` 的话，改动的 HTML 会被静默丢掉。
2. **异常被吞**：插件抛任何 `Throwable` 都会被 `catch` 后写 `Log::error('[addon] hook … failed: …')`（[:50-52](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L50)），页面照常返回。
   → 「插件好像没生效，但没报错」的第一现场是 `runtime/log/`。同理，主类构造失败也只是记一行 `[addon] load … failed`（[:32](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L32)）后当这个插件不存在。
3. **只有 `state=1` 的插件参与**（[:22](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L22) 跳过空/0 状态），且 handler 列表按请求缓存（[:59](file:///D:/wwwroot/maccms/maccms12/app/common/addon/AddonManager.php#L59)）。

|---|---|
| `/addons/<name>` | `controller=index`、`action=index` |
| `/addons/<name>/<controller>` | `action=index` |
| `/addons/<name>/<controller>/<action>` | 全参数 |

参数正则（[:14](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Dispatcher.php#L14)）→ **`state` 必须为真，否则 404**（[:20](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Dispatcher.php#L20)）→
类 `addons\<name>\controller\<Ucfirst(controller)>` 存在（[:25](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Dispatcher.php#L25)）→ 方法存在（[:30](file:///D:/wwwroot/maccms/maccms12/app/common/addon/Dispatcher.php#L30)）；

> 插件自带的 `controller/Admin.php` 想保护后台动作，得自己在 `_initialize()` 里实现（例如 `aicontent` 的做法）。
> 写插件时把敏感动作放进 `controller/`，就等于放进公网；这一点务必按 [09-安全与权限手册.md §9](file:///D:/wwwroot/maccms/maccms12/说明文档/09-安全与权限手册.md) 逐条自检。

## 8. 本地上传 zip：装包时的安全闸门

入口 [Addon::local()](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L485)。流程与限制按代码顺序：

1. **POST + `__token__`**（[:487-496](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L487)）。
2. 文件只接受 `zip`，上限 10240000 字节（≈9.8 MB，[UploadCheck::checkError](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L503)）。
3. 原始包落到 `runtime/addons/<uniqid>.zip`，解压暂存目录 `runtime/addons/stage_<uniqid>/`（[:509-529](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L509)）。
4. [extractZipSafe()](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L52)：
   - 没有 `ZipArchive` 类 → 直接返回 `admin/addon/zip_unavailable`（[:54](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L54)）。
   - 条目数 > `MAX_ZIP_ENTRIES = 5000`、单文件 > `10240000`、解压总大小 > `52428800`（50 MB）任一击穿即拒绝（[:33-35](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L33)）。
   - 路径规范化 + zip-slip 检查（[normalizeZipEntryRelPath](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L202)）。
   - **黑名单目录**（包内不允许出现这些前缀，[:7-20](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L7)）：
     `application/ app/ config/ route/ static/ thinkphp/ extend/ vendor/ template/ public/ runtime/ addons/`
   - **黑名单扩展名**（[:22-25](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L22)）：`phtml phar php3 php4 php5 php7 phps shtml asp aspx jsp`
     —— 注意 **普通 `.php` 不在黑名单**：插件本来就要带 PHP 代码。
   - **黑名单文件名**（[:27-32](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L27)）：`.htaccess .htpasswd .user.ini web.config`（防止包内文件改写本站的访问控制）。
5. 读暂存目录里的 `info.ini` 拿 `name`，再过一次 `isValidName`（[:545-551](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L545)）。
6. [verifyPackageSignature()](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L270)：
   - 包内**既没有** `package.manifest.json` **也没有** `package.sig` → 返回 `ok=true, msg='skip'`，**默认放行**（[:279-283](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L279)）。
     想让「必须签名」成为硬要求，需要配置 `addon.require_local_signature`——而它读的是 `$GLOBALS['config']['addon']`，
     对应文件 `app/extra/addon.php` **在本仓库并不存在**（见 [02-站点配置参考.md §6](file:///D:/wwwroot/maccms/maccms12/说明文档/02-站点配置参考.md)），所以当前**签名默认完全不强制**。
   - 反之，包内**只放了半个签名**（有 manifest 没 sig 或相反）→ 直接失败 `sig_incomplete`；
     有完整签名但没配公钥（`addon.local_public_key`）→ 失败 `sig_pubkey_missing`，**这个分支不看 `require` 开关**（[:336-342](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L336)）。
     校验内容：manifest 里每个文件 sha256 逐个 `hash_equals`，且**盘上多出的文件也算失败**（防夹带，[:317-326](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonSecureInstaller.php#L317)），最后 `openssl_verify` SHA256。
7. 暂存目录必须有 `<Ucfirst(name)>.php` 主类文件（[:560](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L560)），且 `addons/<name>/` 不能已存在（否则 `haved_err`，重装要先卸载，[:567-571](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L567)）。
8. 拿安装锁 `runtime/addon_market/locks/`（[acquireInstallLock](file:///D:/wwwroot/maccms/maccms12/app/common/util/AddonCloudService.php#L782)）→ `rename` 暂存目录进 `addons/<name>`（跨盘失败则递归拷贝）→
   `Service::check()` → **强制把 `state` 置 0**（装完不自动启用，[:599-602](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L599)）→ 调插件 `install()` → `importsql()` → `refresh()`。
9. 这段里任何异常都会 **递归删掉刚建好的 `addons/<name>/`** 并提示回滚（[:616-622](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Addon.php#L616)）。

> 本机（PHP 无 zip 扩展）的实际表现：`local` 在第 4 步就报「服务器未启用 zip 扩展」，**上传安装整条路不通**；
> `uninstall` 也过不去（备份失败即中止，见 §5.3）。生产环境装插件前请确认 `php -m | grep zip` 有输出。

## 14. 上线自检

1. `php -m` 里有 `zip`、`curl`、`openssl`；否则「本地装插件 / 云安装 / 卸载回滚 / 包签名」四项能力会分别失效。
2. 逐个确认 `addons/` 下的插件：不需要就**卸掉目录**（只停用不影响攻击面，但插件页路由在 `state=1` 时对外可达，见 §7 的警告）。
3. 对每个 `state=1` 的插件，读它的 `controller/` 目录，确认敏感动作自带鉴权；把 URL `/addons/<name>/<controller>/<action>` 拿浏览器直接访问一次，验证是否 404/403 而不是执行成功。
4. 把 `app/extra/addons.php` 纳入部署校验：它是派生文件，任何手工编辑都会被下一次 `refresh()` 覆盖。
5. 若使用云市场：确认 `addon_cloud.status`、`rate_limit`、`catalog_url` 三项，并公钥验签已真正配置（不是靠默认空常量「跳过」）。
6. 想收紧上传包：建 `app/extra/addon.php` 提供 `addon.require_local_signature` 与 `addon.local_public_key`（当前**不存在**，签名默认不强制）；生成密钥与 manifest 的做法见
   [app/data/addon/docs/local-package-signing.md](file:///D:/wwwroot/maccms/maccms12/app/data/addon/docs/local-package-signing.md)。
7. 云安装审计文件 `app/extra/addon_market_audit.php` 若已生成，确认它不出现在可下载清单之外——它落在 `app/extra/`，已被内部文件五层拦截覆盖。
8. 清一次 `runtime/cache/`（`hooks`、`addons` 两个键）再验证插件行为，避免拿旧 handler 列表判断。
