## 1. 计划任务：端点与鉴权现状

```
http://你的域名/api.php/timming/index[.html][?name=任务名][&enforce=1]
```

- 处理器 [app/api/controller/Timming.php::index()](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L20)。
- **这是公网无鉴权端点**。后台基类为它开了豁免：`ENTRANCE=='api' && 控制器 Timming && 动作 index` 时**跳过登录校验**
  （[app/admin/controller/Base.php:35](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Base.php#L35)，空分支即放行）。豁免存在的原因是任务处理器会直接 `new` 后台控制器（`Timming.php:100/106/113/121/128`）。
  `api/Base.php` 与 `common/controller/All.php` 也不校验任何 token。
- ⚠️ **`monitor.cron_token` 与计划任务无关**。它只保护监控心跳 `/api.php/monitor/cron`（GET `?token=`，`hash_equals`，长度 <16 直接 403，
  [app/api/controller/Monitor.php:14-23](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Monitor.php#L14)）。别把它当成 timming 的钥匙。
- 因此**唯一的节制是时间窗**（§2）+ `status` 开关。任何知道 URL 的人都能触发采集、清缓存、生成静态。
  部署时请任选其一：Web 层给 `/api.php/timming` 加 IP 白名单；只在 `localhost` 上 `curl` 自己；或把这几条任务 `status` 置 `0`、只留聚合类任务。
- 防爬中间件对该端点显式豁免（[app/common/middleware/AntiScrape.php:69](file:///D:/wwwroot/maccms/maccms12/app/common/middleware/AntiScrape.php#L69)），所以外部 cron 不会被限流挡住——反过来说，它也挡不住别人刷这个 URL。

`enforce=1` 只有在**同一请求带着有效后台会话 Cookie**时才生效（[Timming.php:28-31](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L28)）——
这就是后台列表页「测试」按钮能立刻执行的原因（它 `target="_blank"` 复用浏览器 Cookie，[app/admin/view/timming/index.html:39](file:///D:/wwwroot/maccms/maccms12/app/admin/view/timming/index.html#L39)）。

## 2. 调度判定（四条规则，按优先级）

代码在 [Timming.php:37-57](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L37)。只有 `status === '1'` 的任务参与，然后：

| 条件 | 是否执行 |
|---|---|
| `enforce=1` 且当前请求有有效后台会话 | ✅ 立刻执行 |
| `runtime` 为空（从没跑过） | ✅ 执行 |
| `interval > 0` | ✅ 当 **且仅当** 今天命中 `weeks` **并且** `time() - runtime >= interval` |
| `interval == 0` | ✅ 当 今天命中 `weeks` **并且** 当前小时命中 `hours`（两位 `00..23`） **并且** 上次执行不在「本周期同一小时」 |

> 常见误读：设了 `interval` **并不会**忽略星期几——`$weekOk` 仍是前置条件（`Timming.php:53`）。
> `weeks` 留空会让所有基于星期/间隔的判断都不成立。
> `?name=xxx` 按 `name` 字段**精确匹配**过滤（[:33](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L33)），不是按 id。

**一次 HTTP 请求最多执行一条任务**：命中后 `$this->$file($param); die;`（[Timming.php:81-82](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L81)），
未命中或处理器不存在也 `die`。所以外部 cron 的触发频率必须 ≥ 启用任务条数才能轮完一圈：
14 条全启用 + 每 10 分钟一次 ⇒ 一轮要 ~140 分钟。

## 3. 状态与文件依赖

- 任务清单是 **PHP 数组文件** `app/extra/timming.php`（`return array(键 => array(...))`）。执行前先把 `runtime=time()` **写回该文件**
  （[Timming.php:61-64](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L61) → [mac_arr2file](file:///D:/wwwroot/maccms/maccms12/app/common.php#L280)，内含 `opcache_invalidate`）。
- 所以 **`app/extra/` 必须对 php-fpm 用户可写**；写失败直接返回 `write_err_config`（[:64-66](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L64)）。
- 该文件被 gitignore（[.gitignore:32](file:///D:/wwwroot/maccms/maccms12/.gitignore#L32)）：每次执行都会改动它，入库会造成永久脏文件；安装器从 `app/install/controller/Index.php` 幂等地重建它。
- **执行结果不落盘**：只输出到 HTTP 响应体（[mac_echo()](file:///D:/wwwroot/maccms/maccms12/app/common.php#L470) = `echo …<br>` + flush）。**没有任务日志表、没有执行历史文件**，
  后台列表只显示「上次运行时间」（[app/admin/view/timming/index.html:37](file:///D:/wwwroot/maccms/maccms12/app/admin/view/timming/index.html#L37)）。要看结果就自己把 curl 输出重定向。
- **无并发互斥**：两个重叠请求都会读到旧 `runtime` 并同时跑同一条任务。对照组是监控端有闸门（[app/common/util/MonitorCron.php:9-19](file:///D:/wwwroot/maccms/maccms12/app/common/util/MonitorCron.php#L9) `GATE_SEC=55`），计划任务没有等价实现。
  ⇒ crontab 的间隔要大于任务最长耗时，或自己加 `flock`。
- 入口 `api.php:25-26` 关掉执行时限与内存上限（`max_execution_time=0`、`memory_limit=-1`），长任务不会被 PHP 掐断，但会长期占用一个 fpm 进程。
- 处理器执行前 `reset()` 把 `$_REQUEST` 清空（[Timming.php:90-95](file:///D:/wwwroot/maccms/maccms12/app/api/controller/Timming.php#L90)），避免下游控制器读到外部 GET 参数。

后台维护入口：**网站参数 → 计划任务**（`admin.php/timming/index`；组名 `menu/config`=「网站参数」[zh-cn.php:507](file:///D:/wwwroot/maccms/maccms12/app/lang/zh-cn.php#L507)，条目 `menu/timming`=「计划任务」[:549](file:///D:/wwwroot/maccms/maccms12/app/lang/zh-cn.php#L549)）。
控制器 [app/admin/controller/Timming.php](file:///D:/wwwroot/maccms/maccms12/app/admin/controller/Timming.php)：`index` / `info`（增改，POST 需 Token 校验）/ `del` / `field`（只允许改 `status` 列）。

## 6. crontab 配置写法

```cron
# 每 10 分钟轮一次；启用的任务条数多时请缩短间隔或减少同时启用的任务
*/10 * * * * curl -s "https://你的域名/api.php/timming/index" >/dev/null 2>&1

# 本机自调（推荐，避免把无鉴权端点暴露给公网）
*/10 * * * * flock -n /tmp/maccms-timming.lock curl -s "http://127.0.0.1/api.php/timming/index" >/dev/null 2>&1
```

系统时钟必须与站点时区一致：`weeks/hours` 用的是 PHP 的 `date('w')`/`date('H')`，受 `date.timezone` 影响。

## 7. 缓存体系（「改了不生效」的根因所在）

## 10. 排障速查

| 症状 | 根因 | 处理 |
|---|---|---|
| 计划任务从没跑过 | `status` 是字符串 `'1'`；`weeks` 留空；时区不符 | 后台把开关打开、填星期；核对 `date.timezone` 与 crontab 时钟 |
| 任务跑了但站点没变化 | 结果只回显到 HTTP 响应，不落盘 | 自己把 cron 输出重定向到文件；或看目标表 |
| 同一条任务被反复执行 / 互相覆盖 | 无并发锁 + 一次只跑一条 | 加大 crontab 间隔或用 `flock`；减少同时启用的任务数 |
| 报 `write_err_config` | `app/extra/` 不可写（`timming.php` 回写失败） | 修目录权限；别把 `app/extra/` 设为只读 |
| 采集任务一条不动 | `cjflag != md5(cjurl)` → `code 9001` | 重算 `cjflag`；随包 `aa` 样例的 `cjflag=tv6_com` 是无效值 |
| 采集把全站缓存打空 | `Collect::api()` 完成后强制清缓存 | 把采集排到访问低谷；或改 `cache_flag` 策略 |
| 页面改了不生效 | 三层缓存都可能；列表缓存键无数据版本 | 后台「清除缓存」→ 或改 `app.cache_flag` → 或临时 `cache_core='0'` 验证是不是缓存 |
| 改分类库不生效 | 分类走 `type_list`/`type_tree` 核心缓存 | 删 `{flag}_type_list`、`{flag}_type_tree` 及 `{flag}_{语言}_*` 变体 |
| 后台整站一行白字 | 改了 `Update.php` 没重算 `version.update_hash` | 见 `09-安全与权限手册.md` §5 |
| 异常页泄露 SQL/路径 | `config/app.php` 的 `app_debug=true` 出厂值 | 生产改 `false` |
| 日志目录越涨越大 | 无轮转配置 | 自己加 logrotate / 定期清 `runtime/*/log` |
